# 플래너 편집 계약 보완 (BY-1164, BY-1167)

**목표:** 반복 편집 초기값, 날짜 창 밖의 기록 전체 구간, 과목만 변경할 때 시각·통계 보존을 제공한다.

**기준:** origin/dev `4857433` (플래너 코드는 `80ba4eb`과 동일). 기존 전용 워크트리의 `fix/BY-1167-planner-edit-contract`에서 작업한다. 두 티켓은 재진행 처리했다.

## 원인과 계약

1. 반복은 PUT만 있고 회차 응답에는 계열 id만 있다. `GET /api/planner/tasks/{key}/repeat`를 더해 `seriesId`, `startDate`, `weekdays`, `endDate`를 제공한다. 쓰기와 같은 기준인 **현재 계획 날짜에 유효한 규칙 버전**을 읽는다. 요일 밖으로 옮긴 회차도 기간으로 규칙을 찾는다. 일반 할 일/종료된 계열의 예외에는 `weekdays: []`, 시작·종료일 null을 제공한다. 타인·삭제 회차는 기존 소유/삭제 검증을 따른다.
2. 기록 조회는 묶음 전체를 이미 읽지만 응답의 시작·끝을 창으로 잘라 전체 범위를 잃는다. 기존 `startedAt/endedAt`은 표시 구간을 유지하고 `fullStartedAt/fullEndedAt`을 더한다. 새 필드는 **현재 개인 기록의 절삭 전 구간**으로, 수정본에는 수정된 전체 구간을 담는다. 자정 분할·05시 분할·시간대·DST에 같은 규칙을 쓴다.
3. UPDATE가 시각을 분 단위로 버린 뒤 원본과 비교해 과목만 바꾼 요청도 시간 변경으로 판단한다. UPDATE에서 두 시각을 모두 생략하거나 현재 전체 구간과 정확히 같으면 기존 시각을 그대로 사용한다. 실제로 변경한 경계만 분 단위로 맞추고, 변경하지 않은 경계는 초·소수초를 보존한다. 한 시각만 누락되면 400이다. CREATE의 분 단위 정책은 유지한다.

과목만 변경하는 요청은 기존 총공부·순공을 보존한다. 실제 시간 변경 시 기존 재계산 정책을 따른다. 측정 원본·이벤트·랭킹 구간은 변경하지 않는다. DB 스키마·의존성·SecurityConfig 변경은 필요 없다.

## 구현과 검증

### 1. 반복 설정 읽기

- [x] `PlannerRepeatReadApiTest`: 일반 할 일/유한·무한 반복/규칙 버전/이동한 회차/요일 밖 시작/타인·삭제·미인증을 검증하는 실패 테스트를 실행한다.
- [x] `PlannerRepeatResponse`, 서비스 읽기 메서드, 기존 repeat 경로의 GET과 Swagger 예시를 구현한다.
- [x] 읽기→같은 설정 저장→다시 읽기 및 기존 회차/완료 보존을 검증한다.

### 2. 전체 기록 범위

- [x] `PlannerRecordEditContractApiTest`: 04:30~06:00의 양쪽 날짜, 자정 분할, 수정된 수동/측정 기록의 전체 범위 조회 실패를 재현한다.
- [x] `PlannerRecordView`와 두 view 생성 경로에 전체 시작·끝을 추가한다.
- [x] 표시 구간/일별 합계는 그대로이고 전체 구간으로 저장해도 다른 날짜가 사라지지 않음을 검증한다.

### 3. 과목 변경 시 정밀도

- [x] 초·소수초가 있는 측정 기록의 과목만 변경(시각 생략/명시), 변경 후 재시도, 수동 기록, 한 경계 변경/다른 경계 보존의 실패를 재현한다.
- [x] UPDATE 경계 해석을 CREATE와 분리하고 변경 없는 경계를 보존한다.
- [x] 실제 PostgreSQL의 수정본과 일간·과목별·기간 순공, 측정 원본/랭킹 값, 다른 작업 실패 시 원본 보존을 검증한다.

### 4. 계약 문서와 통합 확인

- [x] Swagger와 `docs/api/planner.md`, ADR-0044에 필드 의미·과목만 변경하는 요청 예시를 반영한다.

## 검증 결과

- 기준 코드에서 새 API 테스트 14개 중 13개가 실패한 뒤 구현으로 통과했다.
- 독립 리뷰에서 발견한 분리 수동 묶음의 과목 변경 409, 빈 구간 색칠, 빈 구간 안의 측정 기록 후속 편집 409를 각각 재현하고 수정했다. 원래 과목이 없는 조각도 포함한다.
- 최종 `./gradlew spotlessApply check`: 전체 2,369개 / 플래너 134개, 실패·오류·스킵 0. 포맷·Checkstyle·ArchUnit 포함.
- 독립 리뷰의 남은 P1/P2 없음. DB 스키마·의존성·SecurityConfig 변경 없음.
- FE 계약은 `docs/api/planner.md`와 Swagger에 반영했다. FE 제한 해제·실제 FE/앱 연동은 미수행이며, 이번 보완은 PR 검토 대상으로 dev 머지·배포 전이다.
