# 다국어 닉네임: 기본 닉네임·닉네임 규칙·금칙어 (BY-1135)

- 작성일: 2026-11-04
- 티켓: [BY-1135](https://breathless-youth.atlassian.net/browse/BY-1135) (처음엔 한국어 기본 닉네임만이었고, 다국어까지 한 번에 내기로 범위를 넓혔다)
- 브랜치: `feat/BY-1135-animal-nickname` (워크트리 `.claude/worktrees/animal-nickname`)
- 상태: 설계. 한국어 기본 닉네임 부분은 구현·검증까지 됐고 커밋 전이다(§8)
- 선행 결정: BY-647 닉네임 규칙(이 문서가 대체), ADR-0020·BY-721 API-Version 규칙

## 1. 배경과 목적

가입하면 닉네임이 `포메{랜덤5자리}`로 자동 발급된다. 숫자가 붙어 **봇처럼 보인다**(사용자). 그래서 사람이 지은 이름처럼 보이는
`꾸미는 말 + 동물`(예: `벼락치기하는 수달`)로 바꾼다.

동시에 앱을 해외에 낸다. 대상은 영어권, 일본, 중국 본토, 홍콩, 대만, 인도다. 기본 닉네임도 휴대폰 언어로 주고, 사용자가 직접 짓는
닉네임도 그 언어로 쓸 수 있어야 한다. 해외 사용자가 늘면 우리가 못 읽는 언어의 욕설이 랭킹에 올라올 수 있어 금칙어도 넣는다.
**이 셋을 한 번에 출시한다**(사용자 결정).

## 2. 목표 · 비목표 · 실패로 보는 것

**목표**
1. 새 가입자는 휴대폰 언어에 맞는 목록에서 `꾸미는 말 + 동물` 기본 닉네임을 받는다(언어마다 100 × 100 = 1만 조합).
2. 닉네임이 아직 `포메+숫자`인 기존 유저는 한국어 조합으로 바뀐다.
3. 닉네임 규칙이 다국어를 받는다: 한중일 글자·영어, 최소 1글자 ~ 최대 40칸.
4. 직접 짓는 닉네임의 욕설·사칭을 **비용 없이** 막는다.

**비목표** (이번에 안 한다)
- 그룹 글(그룹 이름·소개·가입 신청 소개·그룹장 메시지) 번역. 사용자가 원하지만 따로 진행한다.
- 앱 화면 문구 번역, 푸시 알림 문구 번역(`포메님이 공부를 시작했어요` 같은 것).
- 인도 문자(데바나가리 등). 인도는 영어로 간다(사용자 결정).
- AI 검사나 유료 API를 쓰는 욕설 판별, 원어민 검수(사용자: "비용은 안 드는 방식으로", 검수자 없음).
- 이미 쓰이고 있는 닉네임 다시 검사하기, 그룹 이름 등 다른 글에 금칙어 적용.
- 닉네임의 연락처 판정(그룹 글에 쓰는 `ContactDetector`). 닉네임에는 적용하지 않는다(사용자 결정).
- 해외 앱 이름(영어·일본어·중국어 표기) 사칭 막기. 이름이 아직 정해지지 않았다(사용자). 정해지면 사칭 목록에 더한다.

**실패로 보는 것** (동작해도 이러면 실패)
- 기본 닉네임이 다시 봇처럼 보인다(숫자·밑줄이 붙은 아이디 꼴).
- 그 나라 사람이 보기에 어색하거나 모욕·은어로 읽히는 기본 닉네임이 나온다.
- 운영 비용이 생긴다.
- 금칙어 오탐으로 정상 닉네임이 막힌다(`assassin`, `Scunthorpe` 같은 경우).
- 랭킹·공부방에서 이름이 깨지거나 겹쳐 보인다.

## 3. 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 기본 닉네임 형식 | 꾸미는 말 + 동물, 언어마다 100 × 100 |
| 꾸미는 말 | 공부 장면. 학생만 겪는 상황(모의고사·기출·신학기·방학·숙제·장학금)은 빼고 성인도 공감할 것. 가벼운 자조 유머는 좋다(벼락치기·기지개). |
| 동물 | 보편적으로 귀엽거나 멋있거나 예쁜 동물. **흔한 동물만**(원앙·문조 같은 덜 알려진 동물은 뺀다). |
| 한국어 목록 | 확정(§4.1, `AutoNicknames.java`). 마지막 수정: `포기 모르는` → `지치지 않는`(12자 한도 때문) |

| 다른 나라 사람에게 보이는 모습 | 번역하지 않고 쓴 글자 그대로("한국어로 보이게") |
| 기본 닉네임 언어 | 휴대폰 언어를 따른다. 인도는 영어 |
| 길이 | 한중일 글자 2칸, 영어·숫자 1칸. 최소 1글자, 최대 40칸 |
| 화면 표시 | 시안 C: 랭킹 목록·공부방 타일은 한 줄 + 말줄임, **랭킹 1~3등 칸만 두 줄** |

| 해외 앱 이름 사칭 막기 | 이번엔 뺀다(이름 미정) |

## 4. 설계

### 4.1 기본 닉네임

**목록 6개**와 꾸미는 말·동물 사이 구분자:

| 목록 | 구분자 | 예 | 출처 |
|---|---|---|---|
| `ko` | 띄어쓰기 | 벼락치기하는 수달 | `src/main/java/project/study/user/nickname/AutoNicknames.java` |
| `en` | 띄어쓰기, Title Case | Caffeinated Capybara | `docs/superpowers/specs/2026-11-04-by1135-nickname-lists/en.json` |
| `ja` | 없음 | 一夜漬けするラッコ | 같은 폴더 `ja.json` |
| `zh-CN` | 없음(`~的` 꼴) | 熬夜复习的考拉 | `zh-CN.json` |
| `zh-TW` | 없음(`~的` 꼴, 대만 어휘) | 熬夜K書的無尾熊 | `zh-TW.json` |
| `zh-HK` | 없음(`~嘅` 꼴, 광둥어 구어체) | 捱夜溫書嘅樹熊 | `zh-HK.json` |

- 외국어 JSON은 조사 에이전트가 웹 조사로 만들었다. 각 파일에 `joiner`, `modifiers`(100), `animals`(100), `examples`, `excluded`(뺀 단어와 이유),
  `conventions`(형식을 정한 근거), `sources`(URL)가 있다. **단어는 그대로 쓴다.** 고치고 싶으면 사용자에게 먼저 묻는다.
- 5개 파일 모두 확인을 마쳤다: 100/100, 중복 없음, 1만 조합 서로 다름, 아래 §4.2 허용 글자 안, NFKC를 거쳐도 그대로, 가장 긴 조합 30칸 이하
  (en 27, ja 30, zh-CN 20, zh-TW 24, zh-HK 22. ko는 12글자=23칸).
- 영어 목록에는 개·개 품종·부엉이·앵무새가 없다. 인도에서 욕·놀림으로 쓰이기 때문이다(의도한 것).

**언어 고르기.** 가입 요청(`POST /api/users`, API-Version 2, `UserRegisterRequest`)에 선택 필드 `language`(BCP 47 태그, 예: `ja-JP`,
`zh-Hant-HK`)를 더한다. 앱은 휴대폰 언어를 그대로 보낸다.

| 받은 태그 | 목록 |
|---|---|
| 없음(옛 앱) | `ko` |
| `ko*` | `ko` |
| `ja*` | `ja` |
| `zh-Hant-HK`, `zh-HK`, `zh-Hant-MO`, `zh-MO`, 광둥어 `yue*` | `zh-HK` |
| `zh-Hant-TW`, `zh-TW`, `zh-Hant`(지역 없음) | `zh-TW` |
| `zh-Hans*`(지역 무관, 먼저 본다), `zh-CN`, `zh-SG`, `zh`(지역 없음) | `zh-CN` |
| 그 밖의 모든 태그(`en*`, `hi-IN`, `es-ES` …) | `en` |

언어 태그를 받는 필드 하나만 더하는 것이라 API 버전은 올리지 않는다(구 앱은 필드를 안 보내고 지금처럼 한국어를 받는다).

**발급 흐름**(한국어로 이미 구현된 것과 같다): 목록에서 무작위로 뽑아 `insertIfAbsent`(on conflict do nothing)로 넣는다. 닉네임이 겹치면
다시 뽑고, 10번 연달아 겹치면 옛 방식 `포메{랜덤5자리}`로 10번 더 시도하고 warn 로그를 남긴다. 이니셜은 닉네임의 첫 글자 단위다
(`Caffeinated Capybara` → `C`, `一夜漬けするラッコ` → `一`).

### 4.2 닉네임 규칙 (BY-647 대체)

| | 지금(BY-647) | 바뀐 뒤 |
|---|---|---|
| 정규화 | NFC + 앞뒤 공백 제거 | **NFKC** + 앞뒤 공백 제거(전각 `Ｏｔｔｅｒ` → `Otter`, 반각 가타카나 → 전각) |
| 길이 | 글자 단위 2~12자 | **1글자 이상, 40칸 이하** |
| 칸 | — | 한글 음절·히라가나·가타카나(`ー` 포함)·한자·`々`·이모지 = 2칸, 나머지 허용 글자 = 1칸 |
| 허용 글자 | 한글 완성형·영문·숫자·이모지·띄어쓰기 | 지금 것 + **히라가나·가타카나·한자(간체·번체)·`々`·`ー`** + **`_` `.` `-`** + **악센트가 붙은 라틴 글자**(`José`) |
| 유일성 | 정확히 같은 문자열만 중복 | **대소문자 무시**(`Otter`가 있으면 `otter` 불가). 간체와 번체는 다른 닉네임(`水獭` ≠ `水獺`) |

- 그대로 두는 것: 원문 256자 상한, 정규화 뒤 코드포인트 100개 상한, 이모지 조합 규칙, 자모 단독·보이지 않는 문자·그 밖의 문장부호는 400(지우지 않고 거부).
  일본어 가운뎃점 `・`도 문장부호라 막는다.
- 1글자 하한은 한자·가나 한 글자 이름(`猫`)과 영어 한 글자를 위해서다.
- 대소문자 무시는 DB에서 강제해야 한다(동시 가입·수정 경쟁). 지금은 `users.nickname` UNIQUE만 있다. 대소문자를 접은 값의 유일 인덱스가 필요하다.
  **기존 데이터에 대소문자만 다른 닉네임 쌍이 이미 있으면 인덱스가 실패한다** → 마이그레이션 전에 dev·운영에서 확인하고, 있으면 사용자에게 보고한다
  (말없이 이름을 바꾸지 않는다).
- 화면 표시(시안 C)는 프론트 몫이다. 서버는 40칸 상한만 지킨다.

### 4.3 금칙어 (비용 없음)

- **언제:** 사용자가 닉네임을 바꿀 때만(`PATCH /api/users/me/profile`과 레거시 경로). 기본 닉네임은 검수된 목록이라 검사하지 않는다.
  대신 **모든 기본 닉네임 조합이 금칙어에 걸리지 않는다는 테스트**를 둔다.
- **무엇으로:** 서버에 둔 금칙어 목록(한·영·일·중 간체·번체). 공개 목록을 가져다 쓴다. 예: Shutterstock의 "List of Dirty, Naughty, Obscene,
  and Otherwise Bad Words"(CC BY 4.0, 여러 언어). 한국어 비속어 목록도 공개된 것을 쓴다. **라이선스를 확인하고 출처 표기를 저장소에 남긴다.**
  번체 변형이 목록에 없으면 목록에 직접 더한다(간체·번체 변환 라이브러리를 들이지 않는다).
- **사칭 이름:** `admin`, `administrator`, `운영자`, `관리자`, `official`, `staff`, `support`, `moderator`, `公式`, `運営`, `管理員`, `管理员`, `官方` 같은
  운영자로 보일 이름과, 앱 이름 `포메`를 단독으로 쓰거나 "공식·운영·팀·관리" 같은 말과 붙인 이름(`포메`, `포메 공식`, `포메운영팀`)을 막는다.
  `포메라니안`처럼 앱 이름이 다른 단어 속에 든 경우는 막지 않는다. 해외 앱 이름은 정해지면 더한다.
- **연락처는 보지 않는다.** 그룹 글처럼 전화번호·도메인·`@아이디`를 막지 않는다(사용자 결정). ADR에 "닉네임은 연락처 판정 밖"이라고 적는다.
- **우회 표기 잡기(목표 동작):**
  - 대소문자·전각, 띄어쓰기와 `_` `.` `-`로 끊어 쓴 것(`F u c k`, `f_u_c_k`)을 잡는다.
  - 흔한 숫자 바꿔치기(`s3x`, `sh1t`)를 잡는다.
  - 한글 초성(`ㅅㅂ`)은 자모 단독이 이미 허용 글자 밖이라 따로 볼 필요 없다.
- **오탐 막기(목표 동작):** 영어는 단어 단위로 본다. `assassin`, `Scunthorpe`, `Cocktail`, `Grape` 같은 정상 단어 안에 우연히 든 욕은 막지 않는다.
  한글·한자·가나는 띄어쓰기 없이 쓰므로 포함 여부로 본다. 다만 짧은 한 글자 금칙어(예: 중국어 한 글자)는 오탐이 많으니 포함 검사에서 빼는 등 조정한다.
- **막혔을 때:** 400 + 형식 오류와 구별되는 에러 코드(예: `NICKNAME_NOT_ALLOWED`). 앱이 그 나라 말로 안내한다. 어느 단어에 걸렸는지는 응답에 넣지 않는다.
- 금칙어로 못 막은 것은 신고·차단(BY-1124)으로 처리한다.

### 4.4 기존 유저 마이그레이션 (구현됨, 번호는 옮긴다)

지금 파일은 `src/main/resources/db/migration/V40__animal_nicknames.sql`인데 **V40은 dev에서 이미 다른 마이그레이션(`V40__user_acquisition_google_ad.sql`)이 썼다.**
ADR-0041이 레인별로 번호를 예약한다(V36~39, V40~43, V50~54). 이 작업은 **V60~64 레인**을 쓰고 ADR에 적는다. 내용: 닉네임이 `^포메[0-9]+$`인 유저에게 아무도 안 쓰는 한국어 조합을 하나씩 준다.
이니셜은 첫 글자, 조합이 모자라면 남은 유저는 그대로, 시작할 때 `LOCK TABLE users IN SHARE ROW EXCLUSIVE MODE`로 배포 중 쓰기 충돌을 막는다.
배포하는 짧은 틈에 옛 서버로 가입해 `포메`로 남은 유저는 같은 UPDATE를 다시 돌리면 된다(여러 번 돌려도 안전).

### 4.5 "닉네임을 직접 바꿨는지" 판별

분석 SQL(`docs/analytics/compare_*.sql`)은 지금 한국어 조합 1만 개를 SQL 안에 박아 판별한다(구현됨). 언어가 6개가 되면 이 방식은 맞지 않는다.
→ `users.nickname_auto boolean`을 둔다. 기본 닉네임으로 가입하면 true, 사용자가 닉네임을 바꾸면 false. 이름을 바꾸는 마이그레이션에서 컬럼을 만들고,
기존 유저는 "바꾸기 직전에 `포메+숫자`였으면 true"로 채운다. 분석 SQL은 이 컬럼을 쓰도록 되돌린다(조합 CTE 삭제).

### 4.6 문서·전달

- Swagger: 닉네임 규칙 문구(`ValidNickname` 메시지 포함), `language` 필드, 새 에러 코드, 프로필 예시.
- ADR: 닉네임 규칙 변경(BY-647 대체)·기본 닉네임 언어 선택·금칙어를 ADR 하나로 남긴다. 번호는 **0044**(0043은 소셜 로그인이 먼저 썼다).
- 프론트 전달(허원일님, 지라 멘션 댓글): `language` 필드, 새 길이·글자 규칙(칸 계산 포함), 대소문자 무시 409, 금칙어 에러 코드, 랭킹 1~3등 두 줄 표시.
- `websocket.html`: STOMP 계약(필드·타입)은 안 바뀐다. 닉네임 길이를 언급하는 곳이 있으면 고친다.

## 5. 내가 정한 것 (사용자가 반대하지 않은 기본값)

- `_` `.` `-` 허용, 대소문자 무시 유일성, NFKC 정규화, 간체·번체는 다른 닉네임, 악센트 라틴 글자 허용.
- 언어 태그가 없으면 `ko`, 목록에 없는 언어는 `en`. 사용자 언어를 따로 저장하지 않는다.
- 금칙어는 닉네임 변경에만 적용, 기존 닉네임은 다시 검사하지 않음, 그룹 글에는 아직 적용하지 않음.
- 앱 이름 사칭은 단독·"공식/운영/팀/관리" 결합만 막고, 단어 속에 든 경우(`포메라니안`)는 허용.
- 기존 닉네임을 바꿨는지는 `nickname_auto` 컬럼으로 판별.
- 마이그레이션은 V60~64 레인, ADR 0044(0041 사용자 시간대, 0042 공부 리듬 알림, 0043 소셜 로그인).
- **기능 토글 없이 한 번에 켠다.** 앱은 원격 웹을 띄우는 껍데기(`apps/mobile`의 `RemoteWebViewHost`)라서, 스토어 업데이트 없이도 웹 배포로
  모든 사용자가 새 화면을 받는다. 지금 웹의 랭킹(`Nickname.tsx`)·공부방 타일(`RoomTile.tsx`)은 이미 한 줄 말줄임이라 긴 이름이 와도 깨지지 않는다.
  `language` 필드는 서버가 없으면 무시하고(`ko`), 서버는 모르는 필드를 무시하므로 웹·서버 배포 순서는 상관없다.

## 6. 제약

- Spring Boot 4 / Java 25 / PostgreSQL, 스키마는 Flyway로만, `ddl-auto=validate`. ArchUnit 규칙(`@Profile` 금지 등)을 지킨다.
- **새 의존성 없이** 만든다. 꼭 필요하면 이유를 먼저 사용자에게 설명하고 승인받는다.
- 기능 구현 시 테스트 함께(서비스 단위, API 통합 — Testcontainers, `MockMvcTester`). `./gradlew check` 통과. 실패 테스트를 지우거나 @Disabled 금지.
- 커밋 전: Codex 2차 리뷰(`codex exec -m gpt-6-luna -s read-only`), 사용자에게 구현 퀴즈 5개(못 맞추면 커밋 안 함).
- **워크트리를 최신 `origin/dev` 위로 옮기고 시작한다.** 분기 뒤 dev에 사용자 시간대(BY-1133: `ProfileUpdateRequest.timeZone`, `UserService` 변경),
  구글 광고 유입(BY-1138), 그룹 공부방(BY-1124, `ContactDetector` 포함), v2.9.0이 들어왔다.
- 브랜치 충돌: 소셜 로그인(BY-1126) 브랜치도 `UserService`의 자동 닉네임 코드를 고친다. 나중에 머지하는 쪽이 정리한다.
- 지라 BY-1135 본문을 넓어진 범위로 고친다.

## 7. 빌더에게 맡기는 것

- 단어 목록을 저장소에 두는 형식(리소스 파일, 자바 상수 등)과 6개 목록을 고르는 구조. 한국어 `AutoNicknames`를 그 구조로 옮겨도 된다.
- 금칙어 목록 출처 선택(라이선스 확인 포함), 매칭 알고리즘 세부, 한 글자 금칙어 처리.
- 에러 코드 이름, 대소문자 무시 유일성을 DB에 구현하는 방법(접은 값 컬럼 또는 함수 인덱스), 마이그레이션 나누기.
- 테스트 구성.

## 8. 이미 된 것 (워크트리, 커밋 전)

- `AutoNicknames.java`(한국어 100 × 100), `UserService` 발급·폴백·이니셜, `V40__animal_nicknames.sql`(번호 옮길 것), Swagger 문구, 분석 SQL CTE.

## 9. 남은 위험

- 금칙어 목록은 완전하지 않다. 신고·차단이 뒤를 받친다.
