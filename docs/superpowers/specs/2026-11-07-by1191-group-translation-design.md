# BY-1191 그룹 이름·소개 자동 번역 설계

2026-11-08 갱신. [지라 BY-1191](https://breathless-youth.atlassian.net/browse/BY-1191), 브랜치 `feat/BY-1191-group-translation`.

## 목적과 범위

사용자가 작성한 그룹 이름과 소개를 한국어, 영어, 일본어, 중국어 간체, 대만 번체, 홍콩 번체로 제공한다. 원문은 보존하고 다른 사용자 작성 콘텐츠와 프론트 화면은 범위에서 제외한다.

## 선택지와 미결정 사항

- Google Cloud Translation NMT: 월 50만 입력 문자 무료이나 기본 모델의 홍콩 지역별 표현 지원은 확인이 필요하다. Google의 맞춤 모델용 언어 변형 안내에서는 홍콩 변형의 기본 모델을 대만 번체로 안내한다.
- Google Translation LLM: 홍콩과 대만을 별도 언어 코드로 지원하지만 입력·출력 문자 모두 유료다. 실제 그룹 문구로 품질을 비교하기 전 최상이라고 단정할 수 없다.
- Azure Translator F0: 표준 번역 월 200만 문자 무료. 번체 중국어와 광둥어를 각각 지원하나 홍콩용 번체 중국어를 무조건 광둥어로 매핑하지 않는다.
- DeepL 신규 API Developer 무료 제공: 총 100만 문자이며 매월 갱신되지 않는다. 기존 API Free 월 50만 문자 요금제는 신규 가입이 중단되었다. 계정의 실제 요금제와 지원 언어를 확인해야 한다.

사용자가 승인한 잠정 공급자 순서는 Google 일반 NMT → Azure F0 → DeepL 무료 잔량 → 원문이다. 이는 전체 대상 언어에서 Google의 품질이 우월하다는 검증 결과가 아니다. 무료 범위에서 실제 그룹 문구의 언어별 번역 품질을 비교하고 필요하면 순서를 조정한다.

DeepL 계정의 API Developer 무료 요금제와 활성 API 키 1개, 포함량 100만 문자를 브라우저에서 확인했다. Google은 `focus-group-translation` 키 생성과 Cloud Translation API 전용 제한을 확인했다. Azure는 활성 `Azure subscription 1`과 소유자 권한을 확인했다. `focus-translation` 리소스 그룹, Korea Central 지역, `focus-group-translator` 이름, Free F0 요금제로 리소스를 배포했고 배포 완료 및 리소스 목록을 확인했다. 인증정보 값은 이 문서에 기록하지 않는다.

## 무료 사용량 통제

- 사용자의 최우선 조건은 번역 비용 0원이다. 유료 요금제 선택·업그레이드·유료 추가 서비스는 허용하지 않는다. 무료 잔량을 확인할 수 없거나 무료 사용을 확신할 수 없는 공급자는 호출하지 않고 다음 무료 공급자 또는 원문으로 돌아간다.
- Google의 무료 크레딧+초과 과금 구조는 절대적 0원 보장과 다르다. 일일 할당량과 서버 카운터가 있더라도 외부 호출·계정 변경·집행 지연까지 보장한다고 설명하지 않는다. 엄격한 무과금 조건이 충족되지 않으면 Google 호출을 비활성화한다.
- Azure는 Translator의 Free F0 리소스만 허용한다. 별도 Foundry LLM·S1·유료 부가 리소스는 만들지 않는다. 무료 한도 소진은 403001 등의 오류로 처리하고 유료 계층으로 전환하지 않는다.
- 사용자가 전달한 브라우저 점검 결과: 프로젝트 `stone-door-503215-g1`의 일반 모델 일일 한도가 10,000자로 설정되었다고 한다. 이 문서 작성자가 콘솔에서 직접 검증한 값은 아니다.
- 최종 목표 한도: Google 콘솔 일반 모델 15,000자/일, 백엔드의 Google 호출 13,000자/일 및 400,000자/월. 요청을 포함해 일일·월간 두 조건을 모두 만족할 때만 호출한다. Google 콘솔 상향은 백엔드 차단 로직 검증 뒤 적용하며, 현재 콘솔 값이 이미 바뀌었다고 간주하지 않는다.
- Google의 일반 NMT 동기 텍스트 번역을 우선 사용한다. 백엔드 일일 한도 × 31일은 403,000자이지만 월간 400,000자에서 먼저 차단한다. Google 콘솔 15,000자 × 31일은 465,000자로 월 무료 500,000자보다 작다. 다른 프로젝트의 사용량·이번 달 기사용량과 설정 적용 시점은 별도로 확인해야 한다.
- Google 일일 사용량의 날짜 경계는 America/Los_Angeles를 사용해 Google의 태평양 시간 자정 초기화에 맞춘다. 사용량은 문자열 길이(UTF-16)가 아닌 전송한 Unicode 코드 포인트 수로 세고, 대상 언어별로 합산한다. 각 재시도도 새로운 호출로 예약한다.
- 서버에서도 공급자 호출 전에 사용량을 원자적으로 예약하고, 동시 요청과 재시작에도 한도를 유지한다. 캐시 조회에는 번역량을 차감하지 않는다. 결과가 불명확한 시간 초과 요청도 예약량을 돌려주지 않아 보수적으로 집계한다.
- Google 일일 또는 서버 월간 한도에 도달하면 Azure F0의 무료 잔량 범위에서 시도한다. 이어 DeepL의 확인된 무료 잔량 범위에서 시도하고, 사용할 수 없으면 원문을 제공한다. Google 일일 제한은 태평양 시간 자정에 초기화된다.
- 이 기능의 Google 호출은 일반 NMT 동기 텍스트 번역에 한정한다. 일괄 번역·LLM·맞춤 모델과 다른 Google Cloud 서비스의 비용까지 이 구현이 통제하는 것은 아니다.
- 계정 수준의 잔여 무료량을 서버가 자동으로 정확히 안다고 가정하지 않는다. 유료 요금제로 자동 전환하거나 한도를 올리지 않는다.

근거: [Google 할당량](https://docs.cloud.google.com/translate/quotas), [Google 요금](https://cloud.google.com/products/translate/pricing), [DeepL 요금제](https://support.deepl.com/hc/en-us/articles/360021200939-DeepL-API-plans).

## 월 사용 규모 계산

정책 확인일은 2026-11-08이다. 반복 무료량은 Google 서버 상한 월 최대 400,000자 + Azure F0 월 2,000,000자 = 약 2,400,000자다. Google 일일 13,000자 때문에 28일인 달은 최대 364,000자, 30일인 달은 최대 390,000자이고, 31일인 달은 월 상한 400,000자가 먼저 적용된다. 현재 콘솔 10,000자가 유지되는 동안에는 Google의 실제 공급량이 더 작다.

DeepL API Developer는 계정 전체에 총 1,000,000자가 추가되는 예비분이며 매월 갱신되지 않는다. 사용량이 0이면 처음에는 합산 약 340만 자를 사용할 수 있지만 이를 매월 무료량으로 안내하지 않는다. 실패·불명확한 시간 초과의 예약량과 다른 사용처의 소비 때문에 실제 성공 번역량은 더 작을 수 있다.

| 사용자당 월 새 번역 입력량 가정 | 약 240만 자로 환산한 월 활성 사용자 수 |
| --- | ---: |
| 100자 | 24,000명 |
| 500자 | 4,800명 |
| 1,000자 | 2,400명 |
| 5,000자 | 480명 |

위 표는 실측 MAU 예측이 아니라 용량을 사용자 수로 바꾸는 가정이다. `새로 공급자에 보낸 원문 글자 수 × 대상 언어 수`가 소비량이며, 같은 번역의 조회 횟수는 소비량이 아니다. 예를 들어 제목+소개 합계 100자를 5개 대상 언어로 새로 번역하면 500자다. 같은 원문·대상 언어를 1만 명이 조회해도 캐시가 있으면 추가 호출하지 않는다. 이 가정에서는 월 약 4,800회의 그룹 전체 문구 번역·수정분을 처리할 수 있으며, 그룹 수와 사용자 수는 같지 않다.

최초 배포 때 기존 그룹을 모든 언어로 일괄 번역하지 않는다. 실제로 요청받은 언어와 필드만 번역한다. 공급자별 예약 문자 수, 캐시 적중률, 원문 대체율을 집계해 실제 사용자당 소비량을 확인한다. 이 수치는 번역 API 용량이며 서버·DB의 동시 접속 처리 능력과는 별개다.

근거: [Google 요금](https://cloud.google.com/products/translate/pricing), [Azure F0 요금](https://azure.microsoft.com/en-us/pricing/details/translator/), [DeepL 요금제](https://support.deepl.com/hc/en-us/articles/360021200939-DeepL-API-plans).

## 응답 계약과 언어

대상은 기존 인증된 GET 네 곳이다. 새 공개 엔드포인트나 Security 설정 변경은 없다.

| 엔드포인트 | 번역 대상 |
| --- | --- |
| `/api/groups/public` | 각 카드의 이름 |
| `/api/groups/public/{groupId}` | 이름·소개 |
| `/api/groups/me` | 각 카드의 이름 |
| `/api/groups/{groupId}` | 이름·소개 |

앱은 선택한 화면 언어를 `Accept-Language`로 전달한다. 서버는 품질값 순으로 첫 지원 언어를 선택하고 `q=0`은 제외한다. 헤더 없음·지원 언어 없음·잘못된 헤더는 원문이며 외부 호출하지 않는다. 영어·일본어·한국어의 지역 변형은 각각 `en`, `ja`, `ko`로 정규화한다. `zh`, `zh-CN`, `zh-SG`, `zh-Hans`, `zh-Hans-CN`, `zh-Hans-SG`는 `zh-CN`, `zh-TW`, `zh-Hant`, `zh-Hant-TW`는 `zh-TW`, `zh-HK`, `zh-Hant-HK`는 `zh-HK`로 정규화한다. 그 밖의 중국어 변형은 임의 추측하지 않는다.

| 앱 언어 | Google NMT | Azure 표준 | DeepL 대상 코드 |
| --- | --- | --- | --- |
| `ko` | `ko` | `ko` | `KO` |
| `en` | `en` | `en` | `EN-US` |
| `ja` | `ja` | `ja` | `JA` |
| `zh-CN` | `zh-CN` | `zh-Hans` | `ZH-HANS` |
| `zh-TW` | `zh-TW` | `zh-Hant` | `ZH-HANT` |
| `zh-HK` | `zh-TW` | `zh-Hant` | `ZH-HANT` |

홍콩과 대만은 앱 언어·캐시를 구분하지만, 이번 무료 표준 모델 구성에서는 같은 번체 번역 코드를 쓴다. 홍콩 특유의 표현이나 광둥어 번역을 보장하지 않는다. DeepL은 무료 계정에서 실제 허용되는 대상 언어를 확인한 뒤 활성화하며, 지원하지 않는 조합은 건너뛴다. 별도 유료 모델을 선택하지 않는다.

기존 `name`, `description`은 원문을 유지한다. 대상 DTO 네 종류에 선택 필드 `translation`을 추가한다.

```json
{
  "name": "새벽 공부방",
  "description": "매일 아침 함께 공부해요",
  "translation": {
    "language": "en",
    "name": "Early Morning Study Group",
    "description": "Let's study together every morning."
  }
}
```

`translation`은 번역 결과가 하나도 없으면 null이다. 객체 안의 각 필드는 해당 번역이 있을 때만 값이 있고 실패·미요청 시 null이다. 앱은 필드마다 `translation?.name ?? name`, `translation?.description ?? description`을 표시한다. 목록에서는 소개를 조회하거나 번역하지 않는다. 원문이 null·공백뿐인 필드는 호출하지 않는다. 번역 결과가 원문과 같아도 정상 성공으로 저장해 반복 호출하지 않는다. 원문 언어는 짧은 제목만 보고 추측하지 않으며 첫 번역 요청의 자동 언어 감지를 사용한다. 원문 이름 검색·정렬·권한 판정은 기존 로직을 유지한다.

## 코드 경계와 요청 흐름

기존 `GroupService`와 `PublicGroupService`는 읽기 트랜잭션에서 원문·권한·멤버 상태를 조회한다. 새 `LocalizedGroupReader`가 그 결과를 받은 뒤 `GroupTranslationService`로 번역을 붙인다. 읽기 서비스가 반환한 이후이므로 공급자 HTTP 호출 동안 기존 읽기 트랜잭션을 유지하지 않는다. 컨트롤러는 이 파사드를 사용하고 저장소에 직접 접근하지 않는다.

1. 기존 서비스가 접근 권한을 확인하고 원문 응답을 만든다. 실패하면 번역 작업도 시작하지 않는다.
2. 언어를 정규화하고 응답에 실제로 있는 이름·소개만 캐시에서 일괄 조회한다.
3. 없는 필드에 대해 짧은 쓰기 트랜잭션으로 10초 작업 임차권을 획득한다. 다른 요청이 처리 중이면 이번 응답은 그 필드의 원문을 쓴다.
4. 캐시 없는 필드를 한 요청의 대상 언어별로 모아 Google → Azure → DeepL 순서로 시도한다. 공급자별 사용량을 먼저 예약하고 DB 트랜잭션을 끝낸 뒤 HTTP를 호출한다.
5. HTTP 대기 총 예산은 조회 요청당 3초다. 한 공급자 시도는 남은 예산과 2초 중 작은 값으로 제한한다. 연결 제한은 최대 300ms다. 남은 예산이 없으면 원문으로 끝낸다. 숨은 자동 재시도는 사용하지 않는다.
6. 성공한 필드는 임차권·원문 일치 조건으로 저장하고 응답에 붙인다. 일부 필드만 성공해도 해당 결과는 사용한다. 실패한 필드를 성공 결과로 덮어쓰지 않는다.

공급자 한 번의 배열 요청은 최대 50개 텍스트·총 5,000 코드 포인트다. 목록 최대 50개 제목은 한 배열에 들어간다. 상세는 이름·소개 두 필드다. 여러 배열이 필요한 경우에도 같은 3초 예산 안에서 처리하고 미처리 필드는 원문을 쓴다. 일반 동기 텍스트 API의 배열 전송이며, 별도 과금 경로인 Google 비동기 Batch Translation은 사용하지 않는다. 실패한 요청도 이미 예약했다면 차감 상태를 유지한다.

## PostgreSQL 캐시와 사용량 예약

새 Flyway 마이그레이션 번호는 ADR-0041의 기존 V50~54 예약 구간 뒤인 V55를 사용한다. Redis·새 SDK 없이 기존 `JdbcClient`, `RestClient`, JDK HTTP 클라이언트를 쓴다.

- `group_translation_cache`: 기본키 `(group_id, field, target_locale)`. `field`는 `NAME` 또는 `DESCRIPTION`. SHA-256 원문 해시, 번역문, 공급자, 임차권 UUID·만료 시각, 다음 시도 가능 시각, 갱신 시각을 저장한다. 원문은 기존 그룹 테이블에만 둔다. 그룹 물리 삭제는 FK cascade로 정리한다.
- `group_translation_provider_state`: 공급자별 잠금 행 3개와 다음 호출 가능 시각. 사용량 예약 시 이 행을 잠가 여러 서버 인스턴스의 동시 호출을 직렬화한다. HTTP 중에는 잠금을 유지하지 않는다.
- `group_translation_usage`: 기본키 `(provider, period_type, period_key)`, 예약 문자 수를 저장한다. `DAY`, `MONTH`, `LIFETIME`을 구분하고 필요한 기간을 한 트랜잭션에서 모두 검사·증가한다. 관리자 리셋 API는 만들지 않는다.

캐시는 사용자가 아니라 그룹·필드·대상 언어 단위로 공유한다. 생성·수정 시 별도 번역을 선실행하지 않는다. 현재 응답 원문의 해시가 다르면 그 필드의 옛 번역은 사용하지 않고 다시 처리한다. 소개만 바뀌면 이름 캐시는 유지한다. 성공 결과에는 시간 만료를 두지 않는다.

임차권 획득과 결과 저장은 해당 그룹이 살아 있고 DB의 현재 필드가 작업의 원문과 일치할 때만 허용한다. 저장에는 임차권 UUID·원문 해시도 일치해야 한다. 수정 전 작업이 늦게 완료되어 수정 후 결과를 덮어쓸 수 없다. 응답 원문과 번역은 같은 스냅샷에 대응해야 하며, 이미 진행 중인 조회가 수정 직후의 최신 원문을 항상 보장한다는 의미는 아니다. 원문 불일치·그룹 삭제 시 그 결과는 버린다.

프로세스 중단·네트워크 불명확성 때문에 외부 요청의 엄밀한 1회 실행은 보장하지 않는다. 임차권 안에서는 중복 실행을 막고, 만료 후 새 시도도 사용량을 새로 예약한다. 전체 실패 시 필드별 60초 재시도 대기 후 다시 시도한다. 정상 번역을 원문 대체 결과로 영구 캐시하지 않는다.

| 공급자 | 서버 한도 | 날짜·기간 |
| --- | --- | --- |
| Google | 13,000자/일 AND 400,000자/월 | `America/Los_Angeles` 달력 기준 |
| Azure F0 | 2,000,000자/월 보조 제한 | 서버는 UTC 월 기준, 실제 F0 계정의 무료 주기·잔량이 우선 |
| DeepL Developer | 총 1,000,000자에서 기사용량 차감 | `LIFETIME`, 월초 초기화 금지 |

실제 Azure 과금 주기가 서버 달력과 다르거나 외부 사용량이 있으면 F0 자체 제한에 먼저 도달할 수 있다. 이를 다음 공급자로 전환하며 월 200만 자 전부가 이 앱에 남아 있다고 단정하지 않는다. 첫 활성화 전 공급자별 이번 기간 기사용량을 장부에 반영하고, 전용 키를 다른 호출 경로에서 쓰지 않는다. 장부 누락·DB 오류·사용량 초기화 의심 시 외부 번역을 실행하지 않는다. DeepL의 사용량 조회는 무료 잔량 확인에 쓰되, 그 응답의 월간 값으로 영구 누적 장부를 감소시키지 않는다.

예약량은 실제 전송 원문 문자열의 `codePointCount` 합계이며, 대상 언어별·각 공급자 시도별로 계산한다. 예산보다 큰 배열은 필드 경계에서 허용되는 만큼만 예약하고 나머지는 다음 공급자로 보낸다. 요청 순서는 그룹 ID·필드 순으로 정해 동시 테스트를 재현 가능하게 한다. 공급자에게 전송하기 전에는 빈 입력과 중복 필드를 제거한다.

## 장애·설정·관측

- 공급자 HTTP 오류, 응답 개수 불일치, 빈 번역문, 네트워크 오류는 다음 무료 공급자로 넘긴다. 유효하지 않은 응답 전체를 성공 캐시하지 않는다. 사용자에게는 그룹 조회를 성공시키고 해당 필드는 원문으로 제공한다.
- Google 일일/월 한도 초과는 해당 기간 말까지 건너뛴다. Azure `403001`·DeepL `456` 또는 잔량 없음은 공급자 대기 상태로 두며 잔량 재확인 전 다시 호출하지 않는다. 인증 실패는 설정 수정까지 공급자를 중지한다. `429`는 `Retry-After`를 따르고 없으면 60초 대기한다.
- 전역 `app.group-translation.enabled` 기본값은 false다. 꺼져 있으면 캐시·공급자 호출 없이 기존 원문 응답을 반환한다. 공급자별 enabled도 기본 false다. Google은 장부·한도 검증 및 무료량 확인 후에만 켠다. Azure는 F0, DeepL은 Developer 무료 계정과 무료용 endpoint만 사용한다.
- 인증정보는 환경 변수 또는 gitignore된 로컬 설정에 주입한다. 환경 변수 이름은 `GOOGLE_TRANSLATION_API_KEY`, `AZURE_TRANSLATION_API_KEY`, `AZURE_TRANSLATION_REGION`, `DEEPL_TRANSLATION_API_KEY`다. 엔드포인트는 서버 설정으로만 주입하며 클라이언트 입력을 받지 않는다.
- 공급자 이름·정규화 언어·성공/대체 사유별 기존 Micrometer 카운터를 사용한다. 그룹 ID·사용자 ID·원문·키는 메트릭 태그에 넣지 않는다. 요청/응답 본문·인증 헤더·키가 포함될 수 있는 공급자 예외를 그대로 로그에 남기지 않는다.
- 롤백은 전역 설정 off다. 기존 원문과 권한 응답은 유지한다. WebSocket 계약은 변경하지 않는다.

## 검증과 활성화 조건

언어 정규화, 무료 한도 직전·초과·동시 예약, 재시작 후 누적량, DST/월 경계, 영구 DeepL 장부, Unicode 문자 수, 캐시 공유, 필드별 수정, 늦은 응답, 실패·쿼터·잘못된 공급자 응답, 접근 권한, 기존 응답 호환성을 테스트한다. 외부 HTTP는 JDK `HttpServer` 가짜 서버로 검증하고 PostgreSQL 동시성은 Testcontainers로 검증한다. 네트워크 모의 테스트를 번역 품질 평가로 설명하지 않는다.

실제 키를 설정한 뒤, 사전에 문자 수를 계산한 작은 샘플로 여섯 앱 언어와 공급자별 사용 가능 여부를 점검한다. 제목·소개·공부 용어·이모지·숫자·혼합 언어를 포함하고 지역별 자연스러움은 각 언어에 능숙한 사람이 평가한다. 모든 공급자·언어의 품질이 검증되었다고 사전 선언하지 않는다. 실번역 평가 요청도 같은 무료 장부를 거친다.

구현 후 `./gradlew check` 통과, 독립 리뷰, 커밋 전 사용자 퀴즈 5개를 거친다. 백엔드 제한 검증 전에는 Google 콘솔 한도를 올리지 않는다. 프론트는 별도 작업에서 요청 헤더와 필드별 원문 대체 표시를 연결해야 실제 화면에 번역이 보인다.
