# BY-1162 날짜별 플래너 서버 설계

- 상태: 승인된 제품 기획의 서버 구현안. 구현 시작 지시에 따라 진행한다.
- 제품 원문: frontend `docs/superpowers/specs/2026-11-05-planner-plan-design.md`
- 티켓: BY-1162, BY-1163~BY-1169

## 계약

새 API는 `/api/planner`, API-Version 1, 토큰 인증이다. 기존 `/api/subjects/day`는 그날 존재했던 과목이며 유지한다. 플래너 응답은 직접 선택한 과목, 그날 할 일이 있는 과목, 실제 공부 기록에 남은 과목의 합집합을 서버에서 만든다. 미래 날짜도 조회한다. 요청의 IANA `timeZone`을 기존 UserTimeZones로 해석하고, 오늘과 하루 창은 현지 05:00으로 계산한다. DST 날짜는 24시간을 더하지 않고 다음 달력 날짜의 05:00을 구한다.

과목 전체 상한 20, 새 이름 12자, 할 일 새 이름 25자다. 기존 긴 이름은 자르지 않는다. 과거 계획의 추가·이름 변경·삭제·과목 선택은 거절하고, 완료·취소와 오늘 이후로의 이동은 허용한다. 미래 완료는 거절한다. 과목별 날짜별 할 일 30개는 일반 할 일과 반복 회차를 합쳐 검사한다. 조회 때 잘라 버리지 않는다. 이력이 한도를 넘는 경우 이력은 모두 보여 주고 추가를 막는다.

## 날짜별 할 일과 반복

기존 `study_task`에 계획 날짜, 반복 계열/원래 회차 날짜, 개별 수정·가져오기 무시 상태를 추가한다. 기존 id와 done_at 및 세션의 할 일 참조는 보존한다. 일반 할 일 키는 `t:<id>`, 반복 회차 키는 `r:<seriesId>:<원래날짜>`다. 아직 저장하지 않은 반복 회차도 이 키로 읽고 변경할 수 있다. 세션에 id가 필요하면 회차를 명시적으로 실체화한다.

반복 규칙은 유효 기간별 버전으로 저장한다. 조회는 날짜에 맞는 규칙과 저장된 회차 예외를 합친다. 완료·이동·이 날만 이름 변경·삭제는 해당 회차만 실체화한다. 앞으로 변경은 이전 규칙의 유효 기간을 닫고 새 버전을 만든다. 과거와 개별 수정된 미래 회차는 보존한다. 안 함은 선택 회차를 일반 할 일로 남기고 이후 규칙을 닫는다. 시작일이 선택 요일이 아니어도 최초 할 일은 남는다.

종료일 없는 반복 한도는 미래 모든 날의 규칙 경계 및 요일 조합과 저장된 예외 날짜를 검사한다. 하루에 30개를 넘기는 규칙 생성·변경은 원자적으로 거절한다. 모든 계획 쓰기는 기존 과목 사용자 advisory 락으로 직렬화한다.

## 목표와 미완료 가져오기

개별 목표와 기본 목표는 따로 저장한다. 개별 값이 없을 때만 기본값을 사용하며, 명시적인 0과 미설정을 구분한다. 목표는 0~86400초, 1800초 단위다. DELETE는 개별 목표를 해제해 기본값을 다시 적용한다. 기본 목표 해제도 지원한다.

미완료 후보는 오늘 이전, 무시하지 않은 회차다. 반복은 오늘 예정 회차가 없을 때 계열별 가장 최근 미완료 회차 하나만 제시한다. 처리 요청은 제시된 키 목록과 선택된 키 목록을 받는다. 선택하지 않은 제시 항목만 다시 묻지 않기로 처리한다. 가져오기 전체는 한 트랜잭션으로 처리한다. 한도·중복·소유 검증 실패 시 이동과 무시 상태를 모두 되돌린다. 응답 유실 후 같은 키를 보내도 중복을 만들지 않는다.

## 기록 편집과 집계

측정 세션 원본과 랭킹 관련 구간은 변경하지 않는다. 개인 플래너용 수정본/삭제 표식을 별도 저장하고 원본을 대체해 읽는다. 처음 측정값에 기대는 기존 랭킹과 통계의 원본은 보존된다. 플래너는 새 기록 조회를 사용하며 기존 자정 기준 기록 API와의 차이를 명시한다. 과목별 그날 순공은 수정된 기록으로 계산한다.

측정 시각 변경은 원본 이벤트와 새 구간의 겹침을 제외하여 순공을 계산한다. 원본 구간 밖으로 늘린 시간은 개인 플래너에서 집중 시간으로 센다. 과목 변경은 새 구간 전체에 적용한다. 수정본은 랭킹 집계에 들어가지 않는다. 수동 기록은 기존 자정 분할 묶음 규칙을 유지한다. 잘못된 구간·24시간 초과·미래·다른 개인 기록과 겹침은 거절한다. 여러 기록 저장은 작업별 독립 트랜잭션으로 성공/실패를 반환하고, 사용자별 operationId와 요청 해시로 재시도를 안전하게 처리한다.

## 이전과 공개

Flyway로 기존 날짜 없는 할 일의 planned_date를 채운다. 미완료는 마이그레이션 시점의 사용자 현지 05시 날짜, 완료는 done_at의 사용자 현지 05시 날짜다. deleted_at과 done_at을 바꾸지 않는다. 해당 날짜의 과목 선택은 중복 없이 넣는다. 검증 SQL과 재실행 가능한 이전 로직의 테스트를 남긴다. 새 스키마 소유 데이터의 계정 병합·탈퇴 처리도 포함한다.

BE 기능 전체와 Swagger 예시·오류·테스트를 함께 준비한다. 이 작업은 배포·공개·FE/앱 코드 변경을 포함하지 않는다. 커밋은 전체 check 및 독립 리뷰 뒤에 한다. 퀴즈는 이번 작업에 한해 사용자 명시 지시로 생략한다.
