# 첫 세션 5분 유도 푸시 A/B 실험 (BY-1070)

- 작성일: 2026-10-29
- 티켓: [BY-1070](https://breathless-youth.atlassian.net/browse/BY-1070) (에픽 BY-165 알림 기능)
- 상태: 구현(2026-10-29)
- ADR: ADR-0037
- 선행 설계: ADR-0035(서버 직접 FCM 발송), ADR-0030(일일 리포트·Amplitude 적재)

## 1. 배경

첫 세션의 순공이 5분 이상인 사용자는 5분 미만인 사용자보다 D1·D7 리텐션이 크게 높다(Amplitude N-Day Bounded, 리턴 이벤트
`study_session_started`). 상관관계라서 5분이 리텐션의 원인인지는 모른다. 알림으로 첫 세션 5분을 늘려 보고, 알림을 받지 않은
대조군과 비교해 두 가지를 확인한다.

1. 알림이 첫 세션 5분 달성을 늘리는가
2. 그렇게 늘린 사람이 더 남는가

알림은 이미 끝난 세션을 바꾸지 못하고, 세션 중에는 앱이 앞에 있어 iOS가 알림을 표시하지 않는다. 그래서 대상은 **가입했지만
첫 세션을 아직 켜지 않은 사람**이다. 첫 세션을 5분 미만으로 끝낸 사람과 세션 화면 안의 유도는 범위 밖이다.

## 2. 확정된 결정 (2026-10-29 대화)

1. **대상**: 가입 후 측정 세션(`MEASURED`)이 하나도 없고 진행 중인 세션도 없으며, 알림 권한이 켜진 토큰이 하나 이상 있는 사용자.
2. **배정**: 대상으로 처음 잡힌 순간 push·control로 반씩 무작위 배정한다. 배정은 바뀌지 않고 control도 기록한다.
   대조군은 알림을 받을 수 있는 사람 안에서 뽑아야 권한을 켠 사람과 아무나를 비교하는 편향이 없다.
3. **발송**: push만 받는다. 가입 N시간 뒤 1회(D0), 가입 다음 날 20:00 1회(D1). 그때마다 첫 세션이 아직 없을 때만 보낸다.
   최대 2회이고 D1 뒤로는 이 실험으로 보내지 않는다. D0만 받는 집단은 두지 않는다 — 두 알림 묶음의 효과만 본다.
4. **조용한 시간**: 22:00~08:00(KST)에는 보내지 않는다. 그 시간에 걸린 D0는 건너뛴다.
5. **따라잡지 않음**: 서버가 멈춰 발송 시각을 놓치면 그 단계는 버린다. 늦은 알림은 실험 일정을 흐린다.
6. **상한**: 사람당 하루 1회(시나리오 무관), 같은 단계는 한 번만.
7. **알림**: 누르면 홈(`/`). `type`은 단계별 값, `push_id`를 새로 싣는다. 문구는 아래 표(2026-10-29 확정).

   | 단계 | 제목 | 본문 |
   |---|---|---|
   | D0 | 5분 집중 습관 만들기 🔥 | 지금 5분만 켜두고 가볍게 시작해보세요! |
   | D1 | 딱 5분만 집중해볼까요? 👀 | 시작이 반이에요. 오늘 하루 끝나기 전에 가볍게 타이머를 시작해봐요! |
8. **주 지표**: 배정된 사람 중 첫 측정 세션의 순공이 5분(300초) 이상인 비율. 첫 세션을 켜지 않은 사람은 실패로 센다.
9. **판정 지표**: 가입일 기준 Bounded D7 — 가입일+7일 당일(KST)에 `study_session_started`가 1건 이상인 비율.
   D1 bounded는 알림을 눌러 연 것만으로 오르므로 판정에 쓰지 않는다.
10. **결과는 DB와 일일 Slack 리포트로 본다.** Amplitude로 집단을 보내지 않는다. 앱으로는 control과 알림을 누르지 않은
    사람을 표시할 수 없고, Amplitude 이벤트는 이미 매일 DB로 적재된다(ADR-0030).

## 3. 저장 (V34)

### `push_experiment_assignment` — 실험 배정

| 컬럼 | 쓰임 |
|---|---|
| `experiment` | 실험 키. 이번은 `first_session_5min` |
| `user_id` | 배정된 사용자 |
| `arm` | `PUSH` · `CONTROL` |
| `assigned_at` | 배정 시각 |
| `first_session_id` | 첫 측정 세션의 첫 조각 id. 첫 세션이 생기기 전에는 null |
| `first_session_at` | 첫 측정 세션의 시작 시각(= 묶음 키) |
| `first_focus_sec` | 첫 측정 세션 묶음의 순공 합 |
| `day7_returned` | 가입 7일 뒤 그날(KST) `study_session_started`가 있었는지. 집계 전에는 null |

PK는 `(experiment, user_id)`. 여러 태스크가 같은 틱에 돌아도 PK가 중복 배정을 막는다(`ON CONFLICT DO NOTHING`).
다음 실험은 키만 바꿔 같은 테이블을 쓴다.

**첫 세션**은 그 사람의 측정 세션 중 묶음 키(`submission_started_at`, 없으면 `started_at`)가 가장 이른 묶음이다. 자정을
넘긴 세션은 날짜별 조각으로 나뉘어 저장되지만 조각들이 묶음 키를 공유하고, 순공은 조각 길이에 비례해 나누되 마지막 조각이
나머지를 가져가 합이 제출값과 같다(`StudySessionSplitter`). 그래서 `first_focus_sec`은 묶음 조각들의 순공 합이다.

`day7_returned`는 Amplitude 적재(`amplitude_daily_event`)로 채운다. 늦게 도착한 이벤트까지 들어오도록 그날과 다음 날의 수신 창이
모두 처리된 뒤에 한 번 채운다. 리포트가 읽는 Amplitude·가입자 창(61·68일)보다 실험이 길어져도 결과가 남는다.

일일 리포트가 읽기 전에 첫 세션 칸이 빈 배정자의 첫 세션을 찾아 한 번 채운다 — 발송을 끈 뒤에도 채워져야 해서 발송
작업이 아니라 리포트가 부른다. 한 번 채운 값은 바꾸지 않는다 — 나중에 세션이
지워지거나 바뀌어도 실험 당시의 값이 남는다. 한 묶음은 제출 한 번에 함께 저장되므로 채울 때 조각이 덜 들어와 있을 일은 없다.

### `push_send` — 발송 기록

| 컬럼 | 쓰임 |
|---|---|
| `push_id` | 발송 한 건의 ID(UUID). 알림 data와 앱 열림 이벤트에 실린다 |
| `user_id` | 받는 사람 |
| `type` | 알림 종류(= FCM `type`·`analytics_label`). 이번은 `first_session_d0` · `first_session_d1` |
| `send_date` | 발송일(KST) |
| `sent_at` | 발송 시각 |
| `fcm_accepted` | FCM이 접수한 토큰 수. 0이면 토큰이 모두 죽었거나 FCM 호출이 실패한 것 |

유니크 `(user_id, send_date)`가 사람당 하루 1회 상한이다(시나리오 무관). D0는 가입일, D1은 다음 날에만 후보가 되므로 같은
단계가 두 번 나갈 일은 없다. 발송 전에 행을 먼저 넣어 자리를 잡고, 넣지 못하면(다른 태스크가 잡았거나 그날 이미 받음) 보내지
않는다. 그래서 FCM 호출이 실패해도 다시 보내지 않는다 — 결정 5와 같은 이유다.

## 4. 발송 작업

`FirstSessionPushScheduler` — 10분마다(KST) 돈다. `app.push.first-session-experiment.enabled`가 `true`일 때만 빈이 생기고,
값이 없으면 꺼진다. 실제 사용자에게 보내는 기능이라 실험을 시작할 날 환경별 yaml에서 켠다.

한 틱의 순서:

1. 지금이 22:00~08:00이면 끝낸다.
   FCM 자격증명이 없어도 끝낸다(BY-1071). 키 없이 돌면 발송은 0건인데 배정과 발송 기록만 남아 발송 집단에 알림을 못 받은 사람이 섞인다. 경고 로그는 한 번만 남긴다.
2. **D0 후보**: 가입 시각 + N이 `[지금 − 10분, 지금)`에 들고, 가입일이 오늘인 사용자.
3. **D1 후보**: 지금이 20:00~20:10이면, 가입일이 어제인 사용자.
4. 후보마다 첫 세션 여부와 알림 권한을 다시 확인하고, 대상이면 배정한다(이미 배정됐으면 그대로 쓴다).
5. `PUSH`이면 `push_send`에 그날 자리를 잡고, 잡으면 `PushSender`로 보낸다. 배정은 `SecureRandom`으로 한다.

틱 시각은 10분 격자로 반올림한다. 스케줄러가 몇 분 늦게 돌아도 창이 빠지거나 겹치지 않는다(5분 넘게 밀리면 깨진다).
후보 창이 틱 간격과 같아서 한 사람은 한 틱에서만 잡힌다. 창을 놓친 사람은 다음 틱에 잡히지 않는다(결정 5).
D0가 조용한 시간에 걸렸거나 그때 토큰이 없던 사람은 D1에 처음 대상이 되어 배정될 수 있다.

예외는 직접 잡아 Sentry로 올린다(`RankingCloseScheduler`와 같다). 한 사람의 발송 실패가 나머지를 막지 않는다.

`N`은 `app.push.first-session-experiment.d0-delay`로 둔다(§8).

### 다른 도메인 조회

대상 판정은 `PushExperimentQueries` 한 쿼리가 `users`·`study_session`·`active_study_session`·`push_token`을 테이블명으로
읽는다. 엔티티를 참조하지 않는 지표 쿼리(SessionFactQueries)와 같은 방식이다.

## 5. `PushMessage` 변경

`pushId`(nullable)를 더한다. 값이 있으면 FCM data에 `push_id`로 싣는다. 테스트 발송은 지금처럼 비워 둔다.
앱은 BY-1030부터 열림 이벤트에 `push_id`를 싣는다.

## 6. 일일 리포트 — 🔔 첫 세션 5분 이상 유도 Push 알림 A/B 테스트 스레드

일곱 번째 스레드를 더한다. `DailyReportService`가 push 도메인에서 배정 사실을 받아 로더에 넘긴다(로더 생성자 인자 상한).
읽기에 실패하면 Sentry에 남기고 null을 넘겨 이 스레드만 "계산 실패"가 된다 — 나머지 리포트는 그대로 나간다. 지표는 모두 배정
기록만 읽으므로 리포트의 61·68일 창과 상관없고, 모두 기준일(어제)이 끝나는 시각까지의 값이다.

집단별로 보여 줄 것(맨 위에 대상·방식·목표를 단어로 쓰고 집단은 발송·미발송으로 부른다. 문구는 `ExperimentRendererTest`가 고정):

| 줄 | 정의 |
|---|---|
| 인원 | 기준일까지 배정된 수 |
| ① 첫 세션 순공 5분 이상 (핵심) | 배정자 중 기준일까지 시작한 첫 세션의 `first_focus_sec` ≥ 300 비율 |
| ② 첫 세션 시작 | 배정자 중 기준일까지 첫 세션이 있는 비율 |
| ③ D7 재방문 (판정) | `day7_returned`가 채워진 배정자 중 true 비율. 아래에 목표 인원(집단당 680명) 대비 진행 |
| ④ 알림 권한 해제 (부작용) | 토큰이 남은 배정자 중 권한이 켜진 토큰이 없는 비율 |

- 대상 줄의 "D0 가입 후 N"은 설정값(`d0-delay`)을 그대로 쓴다. 설정을 바꾸면 리포트 문구도 따라 바뀐다.
- 두 쪽 분모가 모두 있으면 줄 끝에 %p 차이를 쓴다.
- ④에서 토큰이 사라진 사람(발송이 UNREGISTERED로 지움, 앱 삭제 추정)은 비율에서 빼고 따로 센다. 발송을 해야 드러나서 알림
  쪽에만 생기므로 비율에 넣으면 알림 쪽 부작용이 부풀려진다.
- 유의성 검정은 넣지 않는다. 비율과 분수를 보여 주고, 목표 표본이 찬 뒤 사람이 판정한다. 중간 숫자로 실험을 멈추지 않는다.
- 운영에서만 리포트가 돈다. dev에서는 단위 테스트로 계산을 검증한다.

## 7. 테스트

- 단위: 조용한 시간, D0·D1 후보 창, 첫 세션이 생긴 사람 제외, 배정 고정, control 미발송, 하루 상한, 같은 단계 중복 금지,
  리포트 지표 계산(첫 세션 5분·Bounded D7·미적재일 제외).
- 통합(Testcontainers): 배정·발송 기록 upsert의 중복 방지, 각 도메인 조회 쿼리, 자정 분할 세션의 첫 순공이 조각 합으로
  채워지는지와 수동 기록이 첫 세션에서 빠지는지.
- 실기기(dev): 실험을 켜고 `d0-delay`를 짧게 줘 새 설치 기기로 D0 알림 수신·`push_id` 열림 이벤트 확인.

## 8. 미정

- **N(D0 지연)**: 운영의 가입→첫 세션 간격 분포를 보고 정한다. 정하기 전 기본값은 2시간.
- **실험 시작일**: 운영 백엔드 릴리즈와 BY-1030이 든 앱이 스토어에 나간 뒤 운영 yaml에서 켠다.
