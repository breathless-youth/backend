# ADR-0039: 스트릭·공부한 날 기준을 세션 하나 순공 5분으로 낮춘다

- 상태: 승인
- 날짜: 2026-10-31
- 티켓: BY-1080 (상위 BY-1079, 짝 BY-1081)
- 관련: ADR-0007(스트릭은 조회 때 계산), ADR-0009(스트릭 10분), ADR-0012(공부한 날), ADR-0027(인터뷰 3번 그룹)

## 맥락

ADR-0009는 그날 세션 하나라도 순공이 10분 이상이면 스트릭에 잡힌 날로 인정했다. ADR-0012의 "공부한 날", ADR-0027의
인터뷰 3번 그룹 완료 세션, 랭킹 연속 일수는 같은 상수(`MIN_STREAK_FOCUS_SEC`)를 재사용하고, `docs/analytics/`의 핵심
사용자는 같은 값을 SQL에 직접 적어 같은 기준을 쓴다.

스트릭을 이어 가는 문턱을 낮춰 매일 다시 오게 하려고 기준을 5분으로 낮추기로 했다. 순공은 AI가 측정한 값이라 5분도 실제로
집중한 시간이다.

## 결정

1. `MIN_STREAK_FOCUS_SEC`를 600에서 300으로 바꾼다. 판정 방식은 그대로다 — `focusSec` 기준, 하루 합계가 아니라 세션 단위,
   자정 분할 조각은 각각 판정한다.
2. 앱 스트릭만 바꾸지 않고 이 상수를 쓰는 곳을 모두 함께 바꾼다 — 랭킹 연속 일수, 일일 리포트의 공부한 날·연속 공부 규칙·바로
   공부, 인터뷰 3번 그룹, 탐색 SQL의 공부한 날·핵심 사용자. 제품과 지표가 다른 잣대를 쓰면 ADR-0012가 막으려던 어긋남이 다시
   생긴다.
3. 일일 리포트 연속 규칙의 기본 하한(`StudyRules.STUDY_DAY_MINUTES`)은 숫자로 따로 적지 않고 상수에서 계산한다. 기준이 다시
   바뀌어도 "N일 연속 공부" 규칙이 따라온다.
4. 탐색 SQL의 분포 구간(첫 세션 3~10분·10분 이상, 지인 무리 겹침 10분)은 공부한 날 정의가 아니라 구간이라 그대로 둔다.
5. 첫 세션 5분 푸시 실험의 목표값(`ExperimentAnalyzer.FIRST_SESSION_TARGET_SEC`)은 실험 정의라 이 상수에 묶지 않는다.
   지금 값이 같은 것은 우연이다.

## 결과

- 스트릭은 저장하지 않고 조회 때 계산하므로(ADR-0007) 과거 기록에도 바로 적용된다. 5~10분 세션만 있던 날이 공부한 날이 되어
  현재·최장 스트릭과 랭킹 연속 일수가 늘 수 있고, 줄어드는 사람은 없다.
- 일일 리포트의 공부한 날·리텐션·바로 공부 비율과 핵심 사용자 수가 배포한 날부터 늘어난다. 배포 전후 값과 10월 탐색 결과(10분
  기준)는 기준이 다르다는 점을 감안해서 비교한다.
- 인터뷰 3번 그룹이 넓어져 완료 화면 카드를 보는 사람이 늘 수 있다.
- 리포트 규칙 키가 `streak-N-10`에서 `streak-N-5`로 바뀐다. 저장하지 않는 값이라 옮길 데이터는 없다.
- 앱·랜딩 문구는 BY-1081에서 바꾼다. 서버가 먼저 나가도 "10분 하면 이어진다"는 문구는 여전히 맞으므로 서버를 먼저 배포한다.
- Metabase에 저장된 질문은 자동으로 바뀌지 않는다. 머지한 뒤 바뀐 SQL을 같은 이름의 질문에 다시 붙여 넣는다.
