# ADR-0025: 과목 이름은 사용자 안에서 하나, 지운 과목은 같은 이름으로 되살린다

- 상태: 승인
- 날짜: 2026-10-04
- 티켓: BY-874
- 선행: ADR-0021 (과목 > 할 일과 세션 과목 시간), ADR-0022 (순서·색)

## 맥락

과목은 soft delete라 지워도 세션에 쌓인 시간 기록이 남는다(ADR-0021). 그런데 지운 과목과 같은 이름으로 다시 만들면 새
id가 생겨, 기록 화면의 과목별 시간에 같은 이름이 여러 줄로 나온다(dev 208번 계정에서 `국어`가 3줄). 살아있는 과목끼리도
이름 중복을 막는 규칙이 없었다.

## 결정

1. **살아있는 과목의 이름은 사용자 안에서 하나다.** 만들 때와 이름을 바꿀 때 살아있는 다른 과목이 같은 이름을 쓰면 409다.
   이름은 앞뒤 공백을 뗀 뒤 그대로 비교한다 — 대소문자·전각 같은 정규화는 하지 않는다. 지금 이름 그대로 바꾸는 요청은
   통과한다.
2. **지운 과목과 같은 이름으로 만들면 새 과목 대신 그 과목을 되살린다.** `deleted_at`을 비우고 순서만 맨 뒤로 준다.
   id가 그대로라 세션 기록과 누적 시간이 한 과목으로 이어진다. 같은 이름을 여러 번 지웠으면 가장 최근에 지운 것을
   되살린다. 응답은 생성과 같은 201이고 누적 시간이 실려 간다.
3. **되살린 과목의 할 일은 돌아오지 않는다.** 과목을 지울 때 함께 지워진 할 일은 지운 채로 둔다 — 과목을 지운 사용자가
   다시 만들었을 때 예전 미완료 할 일이 한꺼번에 살아나는 쪽이 더 놀랍다.
4. **검사는 서비스에서 한다.** 생성과 이름 변경 모두 사용자 락(ADR-0022) 안에서 살아있는 과목 목록(≤ 20건)을 읽어
   비교한다. DB 유니크 제약은 두지 않는다 — 이미 쌓인 같은 이름의 살아있는 과목이 마이그레이션을 막고, 락이 동시 요청을
   직렬화한다.

## 결과

- 과목 상한(20)은 되살릴 때도 그대로 적용한다. 색은 예전 색을 지키되, 지워져 있던 사이 살아있는 과목이 그 색을 가져갔으면
  새 과목처럼 덜 쓴 색을 다시 받는다 — 되살린 과목이 다른 과목과 같은 색으로 보이지 않게 한다.
- 이름 변경으로 지운 과목과 같은 이름이 되는 것은 막지 않는다. 이때는 id가 둘인 채로 남는다.
- 되살릴 과목을 찾는 조회(지운 과목을 이름으로)용 인덱스는 두지 않는다. 과목 테이블이 작아서이고, 생성이 느려지면
  `(user_id, name)` 부분 인덱스를 추가한다.
- 이미 쌓인 같은 이름 과목의 id는 합치지 않는다. 화면이 이름 기준으로 묶어 보여 준다(frontend BY-874).
