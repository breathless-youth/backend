# ADR-0006: 순공 시간은 앱 제출값을 그대로 저장

- 상태: 승인
- 날짜: 2026-07-24

## 맥락
ADR-0003에서 서버는 검증 + 계산(session_sec, focus_sec, stat_date) + 저장을 담당하기로
했고, focus_sec는 요청값을 무시하고 "총 시간 - 비공부 이벤트 구간 합"으로 재계산했다.
그러나 순공 시간의 원천은 온디바이스 비전 AI다. 서버 재계산은 "앱이 보낸 이벤트 목록이
순공 판정의 전부"라는 가정에 기대는데, 판정 주체가 앱인 이상 이 가정을 서버가 강제할
실익이 없고, 시각(startedAt/endedAt)은 이미 클라이언트를 신뢰하고 있어 일관성도 없었다.
클라이언트 주도 제출 모델(ADR-0003)에 맞춰 순공 시간도 앱 값을 그대로 저장하기로 했다.

## 결정
- 요청의 `focusSec`를 재계산 없이 그대로 저장한다. 이벤트 목록은 상태별 발생 건수
  통계(eventCounts) 용도로만 쓴다
- 서버는 범위 검증만 한다: 0 ≤ focusSec ≤ 세션 총 시간 (위반 시 400)
- 자정 분할(ADR-0005) 시에는 조각 길이에 비례해 배분한다 — 앞 조각들은 내림으로
  배분하고 나머지는 마지막 조각이 가져가, 조각 합이 항상 요청값과 같다
- 총 시간(session_sec)과 통계 날짜(stat_date)는 계속 서버가 계산한다 — 시작/종료
  시각에서 유도되는 값이라 요청으로 받으면 중복이고 두 값이 어긋날 수 있다

## 결과
- ADR-0003의 "focus_sec 서버 계산" 결정을 대체한다
- 시각과 마찬가지로 순공 시간도 클라이언트 신뢰 범위에 들어간다 — 랭킹 등 경쟁 기능
  도입 시 조작 방지 관점에서 재검토 필요 (ADR-0003과 동일한 유보)
- 분할 배분값은 비례 추정치다 — 자정 앞뒤 어느 쪽에서 실제로 집중했는지는 알 수 없다
