# ADR-0017: 배포 시 룸 스냅샷 이어받기

- 상태: 승인
- 날짜: 2026-09-06
- 티켓: BY-626

## 맥락
`RoomService`는 방·참가자 상태를 전부 인메모리(HashMap + 단일 락)로 관리한다. ECS 롤링 배포는
새 태스크가 헬스체크를 통과하면 옛 태스크에 SIGTERM을 보내는데, 그 순간 옛 태스크의 방이 전부 사라진다.
프론트는 STOMP가 끊기면 5초 뒤 자동 재연결해 `/topic/room/{id}`를 다시 구독하고 스냅샷을 요청할 뿐
HTTP `join`을 다시 부르지 않는다. 새 태스크는 그 방을 모르므로 확정에 실패하고, 클라이언트는 스냅샷을
무기한 재요청하는 좀비 방에 갇힌다. 영상은 피어 직결이라 잠시 살아 있지만 시그널링·상태 공유·신규 입장이
전부 막힌다. 운영 중인 서비스라 "아무도 안 쓰는 시간"에 배포한다는 전제를 둘 수 없었다.

## 결정
인프라를 추가하지 않고, **종료 시점의 메모리를 DB에 스냅샷으로 남기고 새 태스크가 첫 미스에서 이어받는다.**

1. **방 ID는 DB 시퀀스(`room_id_seq`, 1,000,000부터)로 발급한다.** 메모리 카운터는 재시작마다 0부터 세서
   복원한 옛 방과 새 방이 같은 토픽을 쓰게 된다. 시작값을 띄운 건 첫 롤아웃의 겹침 구간에 레거시 태스크
   (1부터)와 ID가 충돌하지 않게 하기 위해서다. `nextval`은 컨트롤러가 글로벌 락 밖에서 받아 넘긴다.
2. **종료 훅(`RoomSnapshotLifecycle`, SmartLifecycle phase `Integer.MAX_VALUE`)이 웹서버보다 먼저 멈추며
   `RoomService.exportSnapshot()`을 `room_state_snapshot` 한 행(jsonb)에 쓴다.** 소켓이 닫히기 전이라 상태가
   완전하고, 클라이언트가 재연결하기 전에 스냅샷이 DB에 있다. 방이 없으면 기존 행을 지운다.
3. **새 태스크는 모르는 방을 만났을 때 `RoomSnapshotRestorer`로 2분 이내 스냅샷을 이어받는다.** 트리거는
   STOMP SUBSCRIBE **인가 인터셉터**(`WebSocketConfig.allowSubscribe`)와 HTTP join 두 곳이다. 인가가 참가자
   아님으로 프레임을 버리면 `SessionSubscribeEvent`가 뜨지 않으므로 리스너가 아니라 인가 직전이어야 한다. 읽기(I/O)는 락 밖, 적용(`importSnapshot`)은 락 안 메모리. 복원한 참가자는
   "복원 시각에 끊김(유예 시작)"으로 넣어, 재접속 SUBSCRIBE가 기존 `confirmStomp`의 "유예 중 + 새 세션 =
   복귀"로 처리되고 30초 안에 안 돌아오면 `cleanupExpired`가 회수한다. 새 분기를 추가하지 않는다.
4. **카메라·집중·공부 초는 스냅샷에 실어 마지막 값이 보이게 하되 원본은 클라이언트다.** 프론트가 재연결 시
   상태를 재발행하면 더 정확해진다(FE 보강, 없어도 동작).
5. "스냅샷 없음"은 기억하지 않는다 — 겹침 구간에 옛 태스크가 아직 안 썼을 수 있다. 실제로 복원한 뒤에만
   태스크당 다시 하지 않고, 소비한 스냅샷은 지운다.

## 대안과 기각 이유
- **방 상태의 DB 원본화(라이브 테이블 + 제약)**: 크래시까지 덮지만 단일 락이 공짜로 주던 원자성을 제약·조건부
  갱신으로 전부 다시 만들어야 해 `RoomService`를 재작성하는 규모다. 수평 확장 시 Redis로 또 갈아엎게 된다.
- **Redis(ElastiCache)**: 배포·확장·태스크 간 브로드캐스트를 한 번에 해결하지만 월 비용과 새 장애점이
  생긴다. BY-492에서 "수평 확장 시 재도입"으로 파킹한 결정을 유지한다.
- **배포 시간대 회피**: 운영 중 서비스라 보장할 수 없다.

## 결과와 한계
- 배포(SIGTERM 정상 종료) 중 방이 유지되고 재접속 클라이언트가 같은 자리로 복귀한다.
- **크래시·OOM은 덮지 못한다** — 스냅샷을 못 쓰고 죽으면 지금과 같다. 장애 대응은 DB 원본화/Redis 때.
- 겹침 구간에 스냅샷이 써지기 전 새 태스크로 `join`하는 신규 입장자는 몇 초간 404(재시도로 해소).
- 스냅샷 직후~소켓 종료 사이의 변경은 유실되고, 그 참가자는 복원 뒤 유예 만료로 정리된다.
- 태스크 2개 상시 운영에는 맞지 않는다. 수평 확장 시 Redis로 옮기며 이 스냅샷 경로는 걷어낸다.
