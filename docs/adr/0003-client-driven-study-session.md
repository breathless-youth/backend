# ADR-0003: 공부 세션은 클라이언트 주도 일괄 제출로 기록

- 상태: 승인 (focus_sec 서버 계산 부분은 ADR-0006으로 대체, "미종료 세션 없음" 부분은 ADR-0014로 대체)
- 날짜: 2026-07-24

## 맥락
공부 세션(방 입장~퇴장)의 상태(준비/폰사용/이탈)는 React Native 앱의 온디바이스
비전 AI만 감지할 수 있다. 데이터의 원천이 항상 디바이스이므로, 서버가 상태 변경을
실시간으로 추적하는 방식(서버 주도)과 절충안(입장 시 세션 생성 + 퇴장 시 제출)을
검토했다.

## 결정
퇴장 시 세션 전체(시작/종료 시각 + 상태 이벤트 목록)를 API 1개로 일괄 제출받는다.
서버는 검증(시간 범위·겹침·미래 시각) + 계산(session_sec, focus_sec, stat_date) +
저장만 담당한다. 서버에 "미종료 세션" 개념을 두지 않는다.

- 서버 주도 기각: 실시간 표시가 필요해지더라도(차후 WebRTC 멀티) 그 중계는
  별도 실시간 레이어의 몫이며, 기록 저장 경로와는 무관하다.
- 절충안 기각: 앱 비정상 종료 시 입장 기록만 남고 실질 데이터(이벤트)는 어차피
  없다. 진짜 복구는 클라이언트 로컬 백업 + 늦은 재제출로만 가능하고, 이는 일괄
  제출 방식에서도 동일하게 동작한다.

## 결과
- 백엔드 단순화: API 1개, status 컬럼·미종료 정리 로직·스키마 변경 불필요
- 시각은 클라이언트 타임스탬프를 신뢰(검증만 수행) — 랭킹 등 경쟁 기능 도입 시
  조작 방지 관점에서 재검토 필요
- 앱이 로컬 백업 없이 죽으면 해당 세션은 유실됨(프론트 책임으로 위임)
