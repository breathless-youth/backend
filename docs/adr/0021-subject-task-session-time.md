# ADR-0021: 과목 > 할 일과 세션 과목 시간

- 상태: 승인
- 날짜: 2026-09-20
- 티켓: BY-698 (스토리 BY-696)
- 기획 원본: `.ai` 위키 `product/specs/BY-696-과목-시트.md`

## 맥락

세션은 "얼마나 집중했나"(순공·총 공부)만 재고 "무엇을 공부했나"는 남지 않았다. 세션 화면의
과목 시트에서 사용자가 과목 > 할 일을 관리하고, 항목을 선택한 채 잰 시간을 과목·할 일별로 보려면
서버가 과목·할 일을 저장하고 세션 계약에 항목별 시간을 실어야 한다. 앱은 별도 타이머를 두지 않고
세션 타이머(studySec/focusSec)의 값을 선택 전환 시점마다 파생해 보낸다 — 서버 신뢰 모델은 ADR-0006·0008 그대로다.

## 결정

1. **과목·할 일은 별도 도메인(`subject`)의 두 테이블**(`study_subject`, `study_task`)이고 **soft delete**다.
   지워도 세션에 쌓인 시간 기록은 남긴다는 정책(인터뷰 13차) 때문이며, 그래서 세션 제출의 소유 검증도
   삭제 여부를 보지 않는다 — 세션 중 지운 과목 때문에 공부 기록 전체가 거절되면 안 된다.
2. **할 일에 마감일이 없다.** `done_at`만 두고, 목록은 "미완료 전부 + 완료 시각이 오늘(KST)"만 내려준다.
   날짜에 귀속시키면 공부 중 자정을 넘길 때 하던 할 일이 사라지는 문제가 생긴다. 이월·날짜별 회고는
   `done_at`으로 후속 구현할 수 있다.
3. **항목별 시간은 세션의 자식 테이블**(`study_session_subject_time`)이다. `StatusEvent`와 같은
   cascade 컬렉션이라 저장·멱등 대체·삭제가 세션과 함께 움직이고, 자정 분할 때 조각마다 세션과
   같은 가중치(PAUSE 제외 조각 길이 / 이벤트 제외 조각 길이)로 비례 배분한다. 합이 보존되도록
   마지막 조각이 나머지를 가져가고, 두 값이 모두 0인 조각은 행을 만들지 않는다.
   - jsonb 컬럼 안은 기각: 과목 누적이 `subject_id` 합산 한 문장이어야 목록 조회가 싸다.
4. **검증은 범위와 소유만.** 항목 `studySec` 합 ≤ 세션 `studySec`, 항목 `focusSec` ≤ 항목 `studySec`.
   `subjectId`는 토큰 유저의 과목이어야 한다(위반 400). 항목
   `focusSec` 합을 세션 `focusSec`로 다시 묶지 않는다 — 앱이 파생한 값을 이벤트로 역산하지 않는
   ADR-0006과 같은 이유다.
5. **스냅샷·복구에도 같은 필드가 실린다.** `active_study_session.subject_times`(jsonb)에 통째로 덮어쓰고,
   자동 확정은 `create` 재사용이라 항목 시간도 그대로 확정된다. 재접속 복구 응답이 같은 모양을
   돌려줘 앱이 선택 상태와 항목 시간을 되살린다.
6. **소유 검증은 컨트롤러가 `StudySubjectService.assertOwned`를 먼저 부른다.** `StudySessionService`에
   과목 의존성을 넣지 않아 세션 도메인의 순수 검증·분할 로직과 단위 테스트가 그대로다. 자동 확정과
   dev 시더는 이미 검증된 값만 다루므로 거치지 않는다.
7. **구 앱(API-Version 1) 경로는 없다.** 새 필드는 선택이라 구 앱 제출은 기존과 동일하게 동작한다.

## 결과

- 세션 제출·스냅샷·복구 계약에 `subjectTimes[]`가 선택 필드로 추가되고 응답 `StudySessionResponse`에도 실린다.
- `/api/subjects` CRUD 7개가 추가된다. 상한은 과목 20, 과목당 할 일 30. (버전은 2026-09-21 갱신 참고)
- 과목·할 일 누적은 세션 저장 시점에 미리 집계하지 않고 조회 때 합산한다 — 세션 수가 사용자당 수백 건
  수준이라 인덱스(`subject_id`) 합산으로 충분하다. 통계 테이블이 생기면 그때 옮긴다.
- 결과 화면·기록 탭의 과목별 표시는 범위 밖(후속 스토리)이지만, 세션 응답이 항목별 시간을 이미 내려주므로
  서버 변경 없이 붙일 수 있다.

## 갱신 (2026-09-21) — 측정 단위를 과목으로 좁혔다

초안은 **할 일 단위 측정**이었고 그 계약대로 `study_session_subject_time.task_id`와 할 일별 누적
집계를 만들었다. 시안 최종안이 **과목 단위 측정**으로 확정되면서(할 일은 체크리스트) 앱이 그 필드를
채우지 않게 됐고, 서버는 계산해 내려주지만 항상 0인 값이 남았다.

읽는 사람이 계약을 잘못 짚으므로 걷어낸다(V17).

- `study_session_subject_time.task_id` 컬럼과 그 인덱스를 삭제한다.
- `SubjectTimeRequest`·`SubjectTimeResponse`에서 `taskId`를 뺀다.
- `TaskResponse`의 `studySec`·`focusSec`를 뺀다. 할 일은 이름과 완료 시각만 내려간다.
- 세션 제출의 할 일 소유 검증("할 일이 그 과목의 것이 아니면 400")도 함께 사라진다.

`study_task` 테이블과 할 일 CRUD는 그대로다 — 지우는 것은 "할 일별 시간"뿐이다. 할 일 단위 측정이
다시 논의되면 그때 컬럼과 집계를 함께 되살린다.

스냅샷 jsonb(`active_study_session.subject_times`)에 남아 있는 옛 `taskId` 필드는 역직렬화에서
무시된다(Spring Boot 기본 설정이 모르는 속성을 버린다).

## 갱신 (2026-09-21) — 과목 API를 기본버전(1)에 둔다

처음에는 다른 토큰 API와 같이 `version = "2"`로 냈다. 구 앱이 호출하지 않는 새 API라 신·구 계약을
가를 이유가 없어 기본버전 하나로 통일한다(ADR-0020의 병행 장치는 구 앱이 실제로 부르는 경로에만
필요하다). 이 규칙은 ADR-0015 2026-09-22 갱신으로 모든 새 엔드포인트에 일반화됐다.

- 버전은 **라우팅만** 가른다. 인가는 `SecurityConfig`가 정하고 이 경로는 구 앱 예외 목록
  (`LegacyApiRequestMatcher`)에 없으므로 버전 1이어도 토큰이 필요하다. `JwtFilter`는 버전을 보지 않는다.
- ⚠️ Swagger 커스터마이저가 버전 있는 오퍼레이션에 기본값 2를 일괄로 넣고 있었다. 그대로 두면 Swagger
  UI에서 과목 API 호출이 400이라 경로별로 실제 매핑 버전을 넣도록 고쳤다.
- ⚠️ 테스트 헬퍼 `AuthTestSupport.asUser`는 `API-Version: 2`를 함께 싣는다. 과목 API 테스트는 헤더를
  직접 1로 지정해야 라우팅된다.
