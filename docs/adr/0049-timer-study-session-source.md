# ADR-0049: 자율 모드 세션은 TIMER 출처로 저장하고, 경쟁·보상은 관리 모드만, 그룹 공부 시간과 개인 합계는 자율 모드를 포함한다

- 상태: 승인
- 날짜: 2026-11-19
- 이름 변경: 2026-11-20, 카메라 없는 모드의 제품 이름이 "기본 모드"에서 "자율 모드"로 바뀌어 본문을 고쳤다(BY-1356)
- 티켓: BY-1322 (스토리 BY-1321)
- 설계: `docs/superpowers/specs/2026-11-19-BY-1322-timer-session-source-design.md`
- 관련: ADR-0014(자동 확정본 대체), ADR-0020(구 앱 컨트롤러), ADR-0028(랭킹 조회 시 집계), ADR-0031(수동 기록 출처), ADR-0040(그룹), ADR-0044(플래너 기록 수정본), ADR-0047(포인트)

## 맥락

BY-1321은 카메라 없이 공부하는 "자율 모드"를 더한다. AI 카메라로 재는 기존 모드는 "관리 모드"라고 부른다.
자율 모드의 시간은 켜 둔 시간이라 측정의 공정성이 없다. 사용자에게는 공부한 시간이라 개인 기록과 그룹의 함께 공부한 시간에는 보여야 한다.

ADR-0031은 `study_session.source`에 `MEASURED`·`MANUAL`을 두고, 수동 타이머 모드가 생기면 `TIMER`를 더한다고 적었다.
웹은 이미 제출과 체크포인트에 선택 필드 `source`를 보내고 있고, 지금 서버는 이를 무시해 모두 `MEASURED`로 저장한다.

## 결정

1. **`StudySessionSource`에 `TIMER`를 더한다.** `MEASURED`는 관리 모드, `TIMER`는 자율 모드, `MANUAL`은 직접 입력이다.
   `study_session.source`는 V29의 `VARCHAR(16)`이라 스키마 변경이 없다.
2. **제출과 체크포인트는 `source`를 선택 필드로 받는다.** 없으면 `MEASURED`다. `MANUAL`은 400 `VALIDATION_FAILED`다.
   구 앱 요청 record에는 이 필드를 두지 않아 구 앱은 지금처럼 모두 `MEASURED`다.
   TIMER 본문에는 검증을 더하지 않는다. TIMER는 랭킹과 보상에 들어가지 않아 꾸민 값이 남에게 영향을 주지 않는다.
3. **draft도 출처를 갖는다.** V84이 `active_study_session.source`를 `NOT NULL DEFAULT 'MEASURED'`로 더한다.
   체크포인트 UPSERT가 `source`를 덮어쓰고, 덮어쓰기는 기존 `reported_at` 순서 조건을 따른다.
   자동 확정과 복구 확정은 draft의 출처로 세션을 만든다. 최종 제출이 오면 최종 제출의 출처가 이긴다.
4. **제출 묶음 조회는 `MANUAL`이 아닌 출처를 모두 찾는다.** 멱등 재제출, 자동 확정본 대체, 세션 복구, 플래너 `c:` 키가 대상이다.
   이 조회의 뜻은 "세션 API로 제출한 묶음"이라 조건을 `source <> 'MANUAL'`로 쓴다.
   ADR-0031 결정 5가 방어용으로 건 `MEASURED` 조건을 이 뜻으로 바꾼 것이다.
5. **집계는 넣을 출처를 직접 적는다.** 경쟁·보상은 `source = 'MEASURED'`, 그룹 공부 시간은 `source IN ('MEASURED', 'TIMER')`다.
   출처가 또 늘어나도 기존 집계에 몰래 섞이지 않게 하려는 것이다.
6. **출처별로 읽는 곳은 아래와 같다.**

   | 관리 모드만 | 관리 모드와 자율 모드 | 세 출처 모두 |
   |---|---|---|
   | 랭킹 판 전부의 확정 집계, 랭킹 누적 일수 페이스, 명예의 전당 | 그룹 멤버 오늘·이번 주 순공 | 기록 탭 일간 `sessions`·`sessionCount`·`totalStudySec`·`totalFocusSec`·`studiedDatesInMonth` |
   | 랭킹 진행 중 조각(`RankingSource.livePieces`·`settledPieces`) | 공개 그룹 카드 합계·평균 | 기간 통계 |
   | 공개 그룹 목록 정렬 | 그룹 마지막 공부 시각 | 과목 누적 시간 |
   | 공부 포인트, 시작 미션, 마스코트 열림, 상점 연속 일수 | 그룹 책상 공부 상태, 그룹 공부 시작 알림 | 플래너 일간 합계·기간·달력 |
   | 연속 공부, 누적 공부일, 공부 리듬 | 제출 묶음 조회(결정 4) | 홈 05시 하루의 과목 시간 |
   | 기록 탭 일간 `focusRate`·`longestFocusSec`, 플래너 일간의 같은 값 | | |
   | 인터뷰 모집, 첫 세션 푸시, 리듬 알림, Slack 일일 리포트, 시간대 구간 백필 | | |

7. **공개 그룹 정렬은 관리 모드 주간 합계로 한다.** 카드에 보이는 합계·평균은 자율 모드를 포함한다.
   `GroupWeeklyFocus`가 두 합을 함께 계산하고, 정렬용 값은 응답에 싣지 않는다.
   목록 순서는 경쟁이라 ADR-0040이 수동 기록을 뺀 것과 같은 이유로 자율 모드도 뺀다.
8. **플래너 수정본의 출처 CHECK에 `TIMER`를 더한다.** 플래너는 원본 출처를 수정본에 복사하므로 자율 모드 기록을 고치면 `TIMER`가 들어온다.
   원본 없는 수정본을 숨기는 규칙은 `MANUAL`이 아닌 출처 전체에 적용한다.

## 결과

- 응답의 `source`에 `TIMER`가 나온다. `GET /api/study-sessions/active`에 `source`가 생기고, 구 앱 `GET /active`에도 같은 필드가 늘어난다.
- 자율 모드 기록이 있는 날은 일간 합계와 집중률이 서로 다른 세션 집합에서 나온다. 수동 기록과 같은 성질이다.
- 공개 그룹 카드의 합계 순서와 목록 순서가 다를 수 있다. 자율 모드로 합계가 큰 그룹이 뒤에 온다.
- 자율 모드만 한 날은 달력에는 보이지만 연속 공부와 누적 공부일에는 세지 않는다.
- 관리 모드만 봐야 하는 새 집계는 지금처럼 `source = 'MEASURED'`를 직접 걸어야 한다.
- 그룹 공부 시간을 읽는 새 집계는 `IN ('MEASURED', 'TIMER')`를 걸어야 한다.
- 이 배포 전에 옛 서버가 받은 자율 모드 세션은 `MEASURED`로 남는다. 고치지 않는다.

## 고려한 대안

- **TIMER를 수동 기록처럼 다루기**: 제출 묶음 조회와 플래너 키를 손대지 않아도 되지만, 그룹 공부 시간에서 빠지고 재전송·복구가 수동 기록 규칙을 타지 않아 깨진다.
- **집계 조건을 모두 `source <> 'MANUAL'`로 쓰기**: 조건이 짧지만 출처가 늘면 그룹 집계에 묻지 않고 섞인다. 제출 묶음 조회만 이 형태를 쓴다.
- **TIMER 본문 검증 강화(이벤트 금지, `focusSec = studySec`)**: 웹이 일시정지 이벤트를 보내는지 확인해야 하고, 막아도 얻는 것이 없다. 랭킹과 보상에서 빠지는 것으로 충분하다.
- **체크포인트의 출처를 처음 값으로 고정**: 웹이 공부 중에 모드를 바꾸는 흐름이 있으면 마지막 값과 어긋난다. 최종 제출이 이기는 기존 규칙과 맞춰 마지막 값을 쓴다.
