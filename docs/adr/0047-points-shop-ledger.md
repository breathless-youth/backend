# ADR-0047: 포인트는 기록과 잔액을 함께 쓰고 공부 포인트는 날짜별 차액으로 준다

- 상태: 승인
- 날짜: 2026-11-11
- 티켓: BY-1241
- 관련: ADR-0014, ADR-0028, ADR-0043

## 맥락

공부로 포인트를 받고 마스코트 소품과 타이머 배경을 사는 기능을 세 단계로 낸다. 1단계는 공부 적립, 상점, 마스코트다. 2단계는 출석·하루 목표·메달 보상과 그룹 책상의 마스코트다. 이 둘을 함께 만든다. 3단계는 광고와 인앱결제다. 포인트는 3단계에서 돈과 이어지므로 잔액과 지급 여부를 서버가 판단한다.

세션 제출은 같은 요청이 다시 올 수 있고, 자동 확정본은 나중에 온 최종 제출로 지워지고 다시 만들어진다(ADR-0014). 세션 행 id에 지급을 묶으면 두 번 줄 수 있다.

## 결정

1. 잔액을 바꾸는 일은 `point_ledger`에 한 줄을 쓰고 같은 트랜잭션에서 `point_account.balance`를 고친다. `(user_id, reason, ref_key)`가 유일해 같은 지급은 한 번만 들어간다. 잔액은 0 아래로 내려가지 않는다(CHECK). 기록에는 무료(FREE)와 결제(PAID)를 가르는 `fund`를 처음부터 둔다.
2. 한 사람의 적립, 구매, 꾸미기 저장, 마스코트 선택은 포인트 사용자 락(`2^44 + userId`)으로 직렬화한다. 탈퇴·병합의 삭제도 이 락을 잡아, 끝나지 않은 구매가 지운 뒤에 행을 다시 넣어 탈퇴를 실패시키지 못하게 한다.
3. 공부 포인트는 날짜별로 "그날 측정 순공으로 받아야 할 총액 − 그날 이미 준 금액"만 준다. 직접 입력한 기록은 세지 않는다. 날짜는 세션에 저장된 `stat_date`(사용자 시간대 자정)다. 재제출이 와도 받아야 할 총액이 같아 두 번 주지 않고, 한 번 지급이 빠져도 같은 날 다음 제출이 메운다. 지급 실패는 세션 저장을 실패시키지 않는다.
4. 지급은 앱의 세션 제출과 자동 확정 두 곳에서 부른다. 자동 확정본이 먼저 받고 더 긴 최종 제출이 뒤에 오면 차액만 더 준다. 이때 기록 줄이 겹치지 않게 참조 키에 그때까지 준 금액을 넣는다. 최종 제출이 다른 시간대로 와서 날짜가 바뀌거나 쪼개지면, 그 날짜와 앞뒤 하루 가운데 더 받은 날짜에서 모자란 날짜로 차액을 옮긴다(`STUDY_ADJUST` 두 줄, 잔액 변화 없음, 포인트 기록 조회에는 나오지 않음). 참조 키의 제출 시각은 DB에 저장된 값(마이크로초)을 쓴다. 카메라를 켰는지는 가르지 않는다.
5. `app.points.study.starts-on`보다 앞선 날짜의 공부는 포인트를 받지 않는다. 저장된 옛 세션을 다시 제출해 과거 날짜의 포인트를 받아 가는 길을 막는다. 운영은 출시 날짜로 맞춘다.
6. 제출 응답은 배열이라 필드를 더할 수 없다. 결과 화면의 포인트 칸은 `GET /api/points/study-reward`로 따로 준다.
7. 마스코트 해금과 보상 상품의 보유는 저장하지 않고 조회할 때 계산한다(ADR-0028). 누적 순공은 측정 세션만 세고, 연속 일수는 최고 기록으로 견줘 한번 얻은 보상을 잃지 않는다. 그래서 출시 전 공부 기록은 마스코트 해금에만 반영되고 포인트는 0에서 시작한다.
8. 구매 중복은 `user_item`의 `(user_id, item_id)` 기본 키와 락으로 막는다. 두 번째 요청은 `ITEM_ALREADY_OWNED`를 받는다.
9. 상품·가격·마스코트 기준은 `shop_item`, `mascot` 행이다. 마스코트의 이름과 그림은 앱이 코드로 고른다. 앱을 다시 올리지 않고 추가하거나 바꾼다. 30분당 10P와 하루 12시간은 `app.points.study.*` 프로퍼티다.
10. 출석·하루 목표·메달은 받기 요청으로 지급한다. 참조 키가 날짜(출석·하루 목표)와 메달 기록 ID라 한 번만 들어가고, 다시 요청하면 에러 없이 `granted=false`와 잔액을 준다. "오늘"은 공부 포인트와 같이 사용자 시간대의 자정이다.
11. 하루 목표는 플래너·홈의 목표 값을 그대로 쓰고 측정 순공으로만 견준다. 보상은 목표 시간에 비례한다(`app.points.daily-goal.points-per-half-hour`, 기본 30분마다 1P). 목표를 짧게 잡으면 그만큼 적게 받으므로 최소 목표를 따로 두지 않는다. 공부 포인트의 하루 상한을 넘는 목표 시간은 세지 않고, 받는 순간의 목표로 금액을 정해 받은 뒤 목표를 올려도 더 주지 않는다.
12. 메달 포인트는 기간(일·주·월)과 순위로 정하고 종목은 가르지 않는다. 하나씩 받는 요청과 안 받은 메달을 한 번에 받는 요청을 둔다. 포인트 시작 날짜보다 앞선 기간의 메달은 받지 못한다.
13. 상품 이름은 한국어 `name`과 언어별 `names`(jsonb)를 두고 `Accept-Language`의 주 언어로 준다. 번역이 없으면 한국어다. `zh`에는 번체를 넣는다. 구매 기록의 이름도 조회할 때 같은 방식으로 고른다. 분류(`tag`)와 마스코트는 코드만 주고 이름은 앱이 정한다.
14. 그룹 책상에는 멤버가 선택한 마스코트와 그 마스코트가 낀 소품을 싣는다.
15. 비회원(DEVICE)은 포인트·상점·마스코트를 쓰지 못한다(403 `MEMBER_ONLY`). 그래서 계정 병합에서 옮길 포인트 데이터가 없고 옮기는 쪽 행만 지운다.
16. 광고 보상은 앱의 "봤다"는 요청이 아니라 AdMob이 시청을 확인하고 서버로 직접 보내는 콜백(서버 확인)으로만 준다. 콜백은 토큰이 없어 공개 경로(`GET /api/points/ads/admob/callback`)로 받고, 구글 공개 키로 서명을 확인한다. 다른 앱의 광고 단위로 받은 콜백도 구글 서명은 맞으므로, 광고 단위가 `app.points.ad.units`에 있는지 따로 본다. 이 값이 비어 있으면 광고 보상은 꺼져 있다. 참조 키가 콜백의 `transaction_id`라 같은 콜백은 한 번만 들어가고, 하루 한도(기본 3번)는 콜백이 도착한 시각의 사용자 날짜로 센다. 서명이 맞으면 지급하지 않을 때도 200으로 답해 구글이 다시 보내지 않게 한다.

## 결과

- 30분에 못 미친 순공은 버려지지 않고 같은 날 다음 세션과 합쳐진다. 그래서 한 세션이 받은 포인트가 그 세션 순공만으로 계산한 값과 다를 수 있다.
- 상품을 내려도(`active = false`) 이미 가진 사람은 계속 쓴다.
- 상품 종류는 마스코트 소품과 타이머 배경 둘이다. 플래너 꾸미기는 범위에서 뺐고, 다시 넣을 때 `shop_item.category`의 CHECK를 넓힌다.
- 결제 포인트가 들어오면 무료 포인트를 먼저 쓰고, 환불 때는 남은 잔액에서 0까지만 회수한다(충전 구현 때 반영). 지금 `spend`는 FREE로만 기록한다.
- 광고 콜백의 `user_id`는 앱이 넣는 값이라 남의 ID를 넣을 수 있지만, 그 사람에게 포인트가 갈 뿐 받아 올 수는 없다.
