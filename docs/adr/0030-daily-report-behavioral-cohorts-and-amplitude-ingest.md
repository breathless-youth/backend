# ADR-0030: 일일 리포트를 행동 코호트 중심으로 재구성하고 Amplitude를 일 단위로 적재한다

- 상태: 승인
- 날짜: 2026-10-13
- 티켓: BY-904
- 설계: `docs/superpowers/specs/2026-10-13-daily-report-v2-design.md`
- 관련: ADR-0009(스트릭 기준), ADR-0012(헤비유저 정의·지표를 백엔드에)

## 맥락

BY-461의 일일 리포트는 숫자 나열(헤비유저 수, 세션 건수, 소셜 vs 싱글 평균, 코호트 첫주 평균, 상위 20명 세션 목록)이라 팀이 읽고도
결정을 내리지 못했다. 리포트로 하려는 결정은 기능 우선순위와 타겟 유저 정의이고, 이를 위해 "어떤 유저가 남고, 남는 유저는 첫 주에
무엇을 했나"를 매일 보고 싶다. 서버 DB에는 공부·방·과목·D-day 기록만 있고, 화면 단위 행동(앱 실행, 배경음, 플래너, 초대 공유 등)은
FE가 Amplitude로만 보낸다. 규모는 하루 가입·DAU 수십 명, Amplitude prod 이벤트 하루 4~6천 건(2026-10-13 실측)이다.

## 결정

1. **세그먼트는 명시적 행동 규칙으로 정의하고 규칙 문장을 메시지에 그대로 쓴다.** 규칙 이름은 코드 파라미터에서 만든다 — 설명과 판정이
   어긋날 수 없게. 고정 규칙은 "가입 후 첫 7일 중 공부한 날 3일 이상"(ADR-0012 헤비유저와 같은 잣대를 가입 첫 주에), 자동 탐색은
   40개 후보 규칙.
2. **결과 지표는 2주차 리텐션(D7~D13 중 공부한 날 1일 이상)이다.** 행동 기간(D0~D6)과 겹치지 않게 해 "공부를 많이 한 사람이 공부를
   많이 했다" 같은 동어반복을 피한다. 전체 흐름은 D1/D7/D30으로 따로 본다.
3. **노출과 순위는 Amplitude Compass 기준을 따른다.** 각 쪽 5명 이상, 해당 비율 10~90%, phi 상관 0.2 이상만 보이고 상관 순으로 정렬한다.
   %p 차이·배수 정렬은 기각 — 작고 극단적인 그룹이 1위로 올라온다.
4. **Amplitude는 매일 Export API로 받아 유저×날짜×이벤트 횟수로 적재하고, 리포트는 DB만 읽는다.** 리포트 때 다운로드하는 안(장애 시
   섹션 누락, 매일 6주치 재다운로드)과 Amplitude 차트 API 안(서버 기준 "공부한 날"을 못 쓰고 유저별 프로필 불가)은 기각.
   원본 이벤트는 저장하지 않는다.
5. **적재 단위는 수신 시각 기준 KST 하루 창이고, 창 하나 = 트랜잭션 하나다.** Export의 기간은 이벤트 발생 시각이 아니라 Amplitude
   서버 수신 시각이라, 창을 수신 시각으로 자르고 날짜는 발생 시각으로 매긴다. 처리 기록을 PK로 선점해 재실행·태스크 중복에도
   한 번만 센다. 누락된 창은 다음 실행이 채운다.
6. **Amplitude가 미수집인 기간은 0으로 세지 않는다.** 해당 항목을 "미수집"으로 표시하고 탐색에서 뺀다 — 0으로 세면 "그 행동을 안 한
   사람"으로 잘못 잡힌다.
7. **별도 배치 인프라는 두지 않는다.** 서버 안 `@Scheduled`가 제출만 하고, 작업은 metrics 전용 단일 스레드에서 돈다. `TaskScheduler`·
   `Executor` 타입 빈은 만들지 않는다 — 만들면 Boot 기본 스케줄러·실행기 자동 구성이 물러나 다른 스케줄러까지 그 빈으로 돈다.
   재검토 신호: 리포트 생성 수 분 초과, 리포트 쿼리가 API 응답에 영향, ECS 태스크 2개 이상, 다운로드 크기 상한(200MB) 초과 알림.
8. **Slack은 봇 토큰으로 요약 1개 + 스레드 댓글 5개를 보낸다.** Incoming Webhook은 스레드를 못 단다.

## 결과

- ADR-0012의 "지표 정의는 백엔드 도메인 코드에, BI 인프라는 두지 않는다"는 그대로 유지된다. Amplitude는 원천 데이터일 뿐 지표 정의는
  여전히 이 저장소의 코드다.
- ADR-0012의 헤비유저 섹션은 사라지고, 그 잣대(7일 중 3일)는 고정 세그먼트 S1과 "정착" 단계로 이어진다. 자정 분할 조각을
  병합하지 않는 규칙(ADR-0012 결정 3)은 `HeavyUserQueryIntegrationTest` 대신 `UserTimeline` 단위 테스트가 지킨다.
- 상관은 인과가 아니다. 리포트는 실험할 후보를 고르는 도구이고, "규칙 40개 중"과 "3일 연속 Top" 표시로 우연을 걸러 보게 한다.
- 새 시크릿: `AMPLITUDE_API_KEY`, `AMPLITUDE_SECRET_KEY`, `SLACK_BOT_TOKEN`, `SLACK_CHANNEL_ID`. 웹훅(`SLACK_WEBHOOK_URL`)은 전환 확인 뒤 제거.
- 횟수는 여러 창에 걸쳐 가산되므로 창 하나만 다시 받을 수 없다. 잘못 적재된 날을 고치려면 Amplitude 세 테이블을 모두 비우고
  `backfill-days`로 다시 채운다 — 그 기간보다 오래된 이벤트와 `first_seen_at`은 잃는다.
