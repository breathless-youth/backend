# ADR-0048: 스토어 심사용 로그인은 계정 하나만 아이디·비밀번호로 받는다

- 상태: 승인
- 날짜: 2026-11-16
- 티켓: BY-1300
- 관련: ADR-0019, ADR-0047

## 맥락

포인트·상점은 로그인한 사용자만 쓴다. 스토어 심사자에게 Google 계정을 주면 낯선 기기 본인 확인에 막혀 로그인하지 못한다. 심사자는 결제와 계정 삭제까지 시험한다.

## 결정

1. 심사 계정 하나만 아이디·비밀번호로 로그인한다(`POST /api/auth/review-login`). 일반 사용자의 비밀번호 로그인은 만들지 않는다. 심사 계정은 `users.provider = 'REVIEW'`인 회원이고 다른 로그인과 같은 토큰 쌍을 받는다.
2. 설정은 DB 한 행(`review_login`)이다. 아이디, 비밀번호의 BCrypt 해시, 출시된 앱 버전, 처음 상태(포인트, 상품 코드)를 담고 배포 없이 SQL로 바꾼다. 평문 비밀번호는 서버 어디에도 두지 않는다. 행이 없거나 출시 버전이 비어 있으면 꺼져 있다.
3. 요청의 앱 버전이 출시 버전보다 높을 때만 켜진다. 릴리즈할 때 출시 버전을 올리면 그 버전의 앱에서는 입구가 사라지고, 다음 심사 버전에서만 보인다. 앱 버전은 누구나 꾸밀 수 있어 이 조건은 입구를 숨기는 용도일 뿐이고, 막는 것은 비밀번호와 시도 제한이다. 켜짐 여부는 `GET /api/auth/review-login/status`로 조회한다.
4. 틀린 시도는 IP별로 제한한다(10분에 5번). 계정 단위로 잠그면 남이 일부러 틀려 심사자를 막을 수 있다. 하루 전체에 200번을 넘으면 그날은 닫는다. IP는 `X-Forwarded-For`의 맨 끝 값이다 — 운영은 ALB 뒤라 ALB가 붙인 값만 믿을 수 있다.
5. 실패는 401이 아니라 400(`INVALID_REVIEW_CREDENTIALS`)·403(`REVIEW_LOGIN_DISABLED`)·429(`TOO_MANY_REQUESTS`)다. 앱은 401을 토큰 재발급으로 받는다.
6. 심사 계정이 없으면 로그인할 때 만들고 처음 상태를 채운다. 심사자가 계정 삭제를 시험한 뒤 다시 로그인하면 새 계정이 같은 상태로 생긴다. 심사자 여럿이 동시에 쓸 수 있어 로그인할 때 다른 기기의 토큰을 지우지 않는다. 처음 상태에는 마스코트 7종 전부의 보유가 들어간다(BY-1310) — 잠긴 마스코트의 세트는 상점에 보이지 않아, 심사자가 세트를 모두 찾지 못하면 "상품을 찾을 수 없다"로 반려될 수 있다. 보유한 마스코트는 공부 시간 기준과 상관없이 열린 것으로 본다.
7. 심사 계정은 랭킹 집계와 일일 지표 리포트에서 뺀다. 심사자의 결제는 샌드박스로 온다. 운영은 샌드박스 결제를 받지 않지만(누구나 테스트 계정으로 공짜로 받는 것을 막는다) 심사 계정의 샌드박스 결제만은 받는다(BY-1303). RevenueCat의 "Sandbox Testing Access: Allowed App User IDs"와 같은 방식인데, 심사 계정은 삭제 뒤 다시 만들면 결제용 ID가 바뀌어 ID 목록이 아니라 계정 종류로 판단한다.
8. 두 경로는 토큰 없이 열려 있다(Security `permitAll`). 로그인 전이라 토큰이 없기 때문이다.

## 결과

- 릴리즈 절차에 "출시 버전 올리기"가 생긴다. 잊으면 출시된 앱에서도 입구가 보이지만 비밀번호 없이는 들어오지 못한다.
- 비밀번호는 제출할 때마다 바꾼다. 절차는 `docs/runbooks/review-login.md`.
- 심사 계정의 포인트 기록에는 사유 `GRANT`(운영 지급)가 남는다.
