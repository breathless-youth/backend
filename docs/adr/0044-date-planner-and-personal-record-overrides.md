# ADR-0044: 계획 날짜와 반복 예외를 분리하고 개인 기록 수정본으로 측정 원본을 보존한다

- 상태: 승인된 제품 기획의 서버 구현
- 날짜: 2026-11-05
- 티켓: BY-1162, BY-1163~BY-1169
- 관련: ADR-0021, ADR-0025, ADR-0026, ADR-0031, ADR-0038, ADR-0041
- 제품 기획: frontend `docs/superpowers/specs/2026-11-05-planner-plan-design.md`

## 맥락

날짜 없는 할 일로는 미래 계획과 늦게 완료한 지난 계획을 구분할 수 없다. 그날 존재했던 과목(BY-1053)도 그날 선택한 공부 과목과 다르다.
반복의 종료일은 없을 수 있어 미래 회차 전부를 저장할 수 없다. 측정 기록을 개인 플래너에서 편집하더라도 랭킹은 처음 측정값을 유지해야 한다.

## 결정

1. `study_task.planned_date`에 계획 날짜를 둔다. `done_at`은 실제 완료 시각으로 유지하고 완료 개수는 계획 날짜에 귀속한다. 기존 id와 세션의 완료 할 일 참조를 바꾸지 않는다.
2. `planner_day_subject`에는 직접 선택한 과목과 그날 순서만 저장한다. 응답은 직접 선택·할 일·실제 기록의 과목 합집합이다. 기록에 남은 삭제 과목도 포함한다. `/api/subjects/day`의 ‘그날 존재했던 과목’ 계약은 유지한다.
3. `planner_series`와 유효 기간별 `planner_repeat_rule`로 반복을 계산한다. 회차 key는 `r:seriesId:원래날짜`다. 완료·이 날만 이름 변경·이동·삭제는 `study_task`에 예외로 저장하며 `(series_id, occurrence_date)` 유니크가 중복 실체화를 막는다. 원래 요일 밖 시작일의 첫 할 일도 보존한다.
4. 앞으로 변경은 이전 규칙의 유효 기간을 닫고 새 버전을 만든다. 지난 날짜와 개별 수정한 미래 예외는 유지한다. 반복을 끌 때 현재 할 일 id는 유지하고, 이동 때문에 원래 날짜가 되살아나지 않도록 원래 회차 key의 삭제 예외를 보존한다. 앞으로 삭제도 앞선 날짜로 옮겨 완료한 예외를 지우지 않는다.
5. 반복의 날짜별 30개 한도는 규칙 상태가 바뀌는 경계와 저장 예외 날짜/다음 날에서 7요일씩 검사한다. 예외가 첫 주의 표본을 가려도 그 뒤의 일반 주를 검사한다. 사용자 advisory 락으로 계획 쓰기를 직렬화하며 실패한 트랜잭션은 원본·예외·무시 상태까지 되돌린다. 기존 이력을 조회할 때 30개로 잘라 버리지 않는다.
6. 못 끝낸 후보는 계열별 최근 미완료 한 개다. 오늘 예정 회차나 가져온 회차가 있으면 제외한다. 제시한 key와 선택한 key를 함께 받아 미선택 항목만 다시 묻지 않기로 처리한다. 여러 항목의 가져오기는 전체 원자적이며 재요청으로 중복을 만들지 않는다.
7. 기본 목표와 날짜별 목표는 별도 표다. 개별 값이 없을 때만 기본값을 적용한다. 명시적인 0과 미설정을 구분하고 DELETE는 해당 설정을 해제한다. 0~86400초, 1800초 단위를 사용한다.
8. `planner_record_edit`는 개인 플래너용 수정본/삭제 표식이다. 측정·수동 원본 세션과 이벤트·랭킹 구간을 바꾸지 않는다. 새 플래너 조회는 수정본을 합성하고, 기존 자정 통계와 랭킹은 원본을 계속 읽는다. 이 결정은 ADR-0031의 ‘측정 기록을 고치지 않는다’를 **원본 보존 + 개인 표시 편집**으로 확장한다.
9. 시각을 바꾸면 원본 이벤트의 절대 시각과 새 구간의 겹침을 제외한다. PAUSE는 총공부·순공에서, 다른 이벤트는 순공에서 뺀다. 원본 밖 확장은 개인 플래너에서 집중 시간이다. 과목만 바꾸면 현재의 총공부·순공을 유지한다. 수동은 전부 집중이다. 조회 창 분할은 정수 누적 배분을 써 합계가 유실되지 않는다.
10. 기록 배치는 항목마다 독립 트랜잭션이다. `planner_record_operation`의 사용자별 operationId와 요청 해시가 최초 결과를 저장한다. 같은 ID/본문은 결과를 재생하고 다른 본문은 409다. 실패를 보고 조건을 바꿔 다시 저장할 때는 새 operationId를 사용한다. 응답이 유실된 요청을 확인할 때는 같은 operationId로 보낸다.
11. 하루는 현지 날짜 05:00부터 다음 달력 날짜 05:00까지다. 고정 24시간을 더하지 않아 DST도 처리한다. 읽기 요청 timeZone은 저장하지 않고, 쓰기는 기존 UserTimeZones로 기기 시간대를 반영한다. 날짜별 과목/할 일은 달력 날짜 자체이므로 시간대 변경 때 날짜를 다시 변환하지 않는다.
12. V53은 기존 미완료에 마이그레이션 시점의 사용자 05시 날짜, 완료한 할 일에 done_at의 사용자 05시 날짜를 부여한다. 이름·id·done_at·deleted_at·세션 완료 참조를 유지한다. 구 앱에서 날짜 없이 추가한 할 일도 trigger가 같은 기준으로 날짜를 채운다. 새 소유 데이터는 계정 병합·탈퇴 처리기와 전체 소유 컬럼 검증에 포함한다.

## 결과와 대안

2026-11-06 보완(BY-1164, BY-1167): 반복 편집은 쓰기와 같은 현재 계획 날짜의 규칙 버전을 별도 GET으로 제공한다. 날짜 응답의 기록에는 절삭한 표시 시각과 현재 전체 시각(fullStartedAt/fullEndedAt)을 함께 둔다. UPDATE에서 두 시각 생략 또는 현재 전체 시각과 정확히 같은 요청은 기존 초·소수초와 일별 정수 배분을 보존한다. 실제로 바꾼 경계만 분 단위로 맞춘다. 이는 05시를 걸친 기록의 일부가 편집 때 잘리거나 과목만 변경해도 순공이 재계산되는 문제를 방지한다.

2026-11-08 보완(BY-1162): 기록 탭에도 개인 수정본을 반영하기 위해 `/api/planner/records/stats`의 일간·기간·리듬 조회를 추가한다. 기존 `/api/stats`·홈·랭킹·스트릭은 원본을 계속 읽는다. 수정 여부 `edited`는 기존 개인 수정 행의 존재로 계산하므로 과목 없음에도 유지되며 새 DB 컬럼은 필요 없다. 원본과 과목만 바꾼 기록은 기존 statDate와 초를 보존하고, 실제 시각 변경은 연결을 확인한 원본에 저장된 시간대의 자정에서 나눈다. 원본 없는 개인 직접 입력은 요청 시간대로 나눈다. 기존 수정 행에는 입력 당시 시간대가 없어 이를 복원하지 않는다. 이전 수동 기록은 시작 변경 시 새 키를 저장하고 기존 키를 삭제 표식으로 남겨 원본 연결을 잃을 수 있다. 이 경우도 원본 ID와 시간대·완료 참조를 추측하지 않고 `originalSessionId=null`, 완료 참조 빈 배열, 요청 timeZone으로 조회한다. 수정 여부와 개인 시간·삭제 표식은 유지한다. 옛 수동 묶음의 여러 조각 사이 빈 구간은 합계에 넣지 않는다. 수정된 기록의 완료한 할 일 참조는 첫 표시 조각에 한 번만 제공하며 원본 계획일·실제 완료 시각·세션 연결을 변경하지 않는다. 집중률·최장 집중·리듬은 기존과 같이 측정 출처만 대상으로 하되 개인 시간 수정과 삭제를 반영한다. BY-1177 통합 후에는 개인 통계도 공통 순공 1초 기준을 따른다. 1초 미만 조각은 표시하지 않고, 완료 참조는 첫 표시 조각에 한 번만 포함한다.

- 새 플래너는 `/api/planner`(API-Version 1, 토큰)로 계획·개인 기록·목표를 함께 받는다. FE는 기존 자정 조회와 새 플래너 합계를 섞지 않는다. 계약과 이전 검증은 [플래너 API](../api/planner.md)에 둔다.
- 기존 긴 이름은 자르지 않고, 새 과목/할 일 이름만 12/25자로 제한한다. 기존 세션 화면의 할 일 추가도 오늘의 반복 회차 포함 한도를 검사한다.
- 무한 반복을 미리 생성하는 대안은 끝없는 데이터와 규칙 변경 비용 때문에 채택하지 않았다.
- 측정 세션을 직접 변경하고 랭킹 스냅샷을 따로 갱신하는 대안은 여러 랭킹/스트릭/복구 출처를 바꿔야 해서 채택하지 않았다. 개인 수정본은 기존 원본 계약을 보존하는 대신 두 표시 기준을 문서로 구분해야 한다.
- 공개는 FE·앱 연동 검증 뒤 전체 기능을 함께 한다. 이 변경만으로 배포하거나 공개하지 않는다.
