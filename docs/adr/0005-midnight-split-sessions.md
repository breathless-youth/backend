# ADR-0005: 자정을 넘는 세션은 날짜별로 분할 저장

- 상태: 승인
- 날짜: 2026-07-25

## 맥락
ADR-0003에서 세션은 클라이언트 주도 일괄 제출로 확정했고, 자정을 걸친 세션은
"시작 시각의 KST 날짜에 통째로 귀속"하는 MVP 단순화를 택했다. 그러나 일별
통계·캘린더 화면에서 자정 이후의 공부가 전날로 잡히는 문제가 있어, 프론트와
계약을 재논의하며 분할 저장으로 방향을 바꿨다.

## 결정
- 세션이 **KST 자정(00:00)을 넘으면 날짜별 세션으로 분할해 저장**한다.
  예: 24일 23시~25일 01시 제출 → 24일 세션(23~00시) + 25일 세션(00~01시)
- 분할은 도메인(`StudySession.createAll`)이 담당한다. 검증(24시간 한도·미래
  불가 등)은 **분할 전 원본 제출 기준** — 조각별 검증만으로는 자정을 걸친
  25시간 세션이 통과해버리기 때문
- 자정에 걸친 상태 이벤트도 시각 기준으로 나뉘어 각 세션에 귀속된다.
  0초 조각은 버리고, 조각 세션 간 이벤트 엔티티는 공유하지 않는다
- 정확히 자정에 시작/종료하는 세션은 분할하지 않는다
- **제출 응답은 항상 배열**이다 (분할 없으면 1개) — 분할 여부에 따라 응답
  형태가 달라지는 것보다 일관된 계약이 프론트 파싱에 안전하다
- 분할 저장은 한 트랜잭션에서 수행한다 (부분 저장 없음)
- 집중률(focusRate = 순공 ÷ 총시간 × 100, 소수 1자리)을 모든 세션 응답에
  포함하고, 기간 목록 응답은 세션 배열 + 기간 합계(총시간·순공·집중률·상태별
  이벤트 건수)를 담은 래퍼 객체로 변경한다

## 결과
- 일별 통계가 실제 공부한 날짜를 정확히 반영한다 (자정 넘김 공부가 다음날로 귀속)
- 자정에 걸친 이벤트 1건은 기간 조회의 eventCounts에서 **2건으로 집계**된다 —
  각 날짜에 1건씩 귀속되는 의도된 동작이며 스웨거에도 명시함
- 분할된 두 세션을 묶는 링크(부모 ID 등)는 두지 않았다 — 필요해지면
  (예: "한 번의 공부" 단위 통계) 스키마 추가로 재검토
- 제출 응답 배열화·목록 래퍼화는 기존 계약을 깨는 변경이다 (출시 전이라 허용)
