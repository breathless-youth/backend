# ADR-0002: 앱 네이티브 소셜로그인 + 자체 JWT 발급

- 상태: 승인 (ADR-0013에서 재도입, 구글/카카오/애플 3사 지원)
- 날짜: 2026-07-23

## 맥락
프론트가 앱(모바일)이라 Spring의 `oauth2Login()`(브라우저 리다이렉트 + 세션 기반)이 맞지 않는다.
구글은 WebView 내 OAuth를 차단하며(`disallowed_useragent`), 앱에서는 네이티브 SDK 로그인이 표준이다.

## 결정
- 앱이 Google Sign-In SDK로 받은 **ID 토큰**을 `POST /api/auth/login`으로 전송하고,
  서버는 구글 tokeninfo API로 검증(aud = 서버 클라이언트 ID 확인) 후 자체 토큰을 발급한다
- **access 토큰은 JWT**(30분): 일반 API 요청은 서명 검증만으로 처리해 DB를 거치지 않는다
- **refresh 토큰은 opaque UUID**(30일): 어차피 회전·폐기를 위해 DB 조회가 필수라
  JWT 서명 검증까지 하는 이중검증은 불필요하다. SHA-256 해시로만 저장하고,
  재발급 시 행을 지우는 대신 `used_at`으로 마킹(회전)한다.
  사용된 토큰이 다시 오면 탈취 의심으로 해당 유저 토큰을 전부 폐기한다
- 이 방식에서는 서버에 구글 client-secret이 필요 없다 (설정에서 제거됨)

## 결과
- oauth2-client 의존성 제거로 구조 단순화, 앱-서버 계약이 명확해짐
- 프로바이더 추가 시 `OAuthTokenVerifier` 구현체만 추가하면 됨 (카카오/애플 확장 대비)
- 트레이드오프: 로그인마다 구글 API 호출 1회 발생 (JWKS 로컬 검증으로 개선 여지)
