# FocusMakers 릴리즈 QA 체크리스트 (2026-08-28)

다음 `main` 릴리즈 대상. 프론트/백엔드 통합 QA.

- **백엔드**: `dev` 브랜치 (baseline `origin/main`, v1.0.1)
- **프론트**: `feature/BY-452-active-session-restore` 브랜치 (baseline `origin/main`, v0.1.0)
- **대상 환경**: iOS 앱(실기기) · Android 앱(실기기) · **dev 서버 연동**
- **깊이**: 해피패스 + 엣지·에러·경계·동시성·복원 레이스까지

## 범례

- 체크박스: `[ ]` 미검증 / `[x]` 통과 / 실패 시 항목 아래 메모
- 플랫폼 태그: `[iOS]` `[AND]` `[공통]` `[서버]`(=클라 관찰 불가, DB/테스트로만 검증)
- 우선순위: **P0**(릴리즈 게이트, 핵심 흐름) · **P1**(중요 엣지) · **P2**(드문 엣지)
- API 표기는 dev 서버 기준. 조회는 인증 파킹 상태라 `userId` 쿼리로 스코핑.

## ⚠️ 스코프 경고 (먼저 읽을 것)

1. **인증(소셜 로그인 구글/카카오/애플·JWT·refresh)은 이번 dev 빌드에서 코드 비활성**이다.
   `AuthController`/`SecurityConfig`의 JwtFilter가 주석 처리돼 `/api/auth/*` 엔드포인트가 없고,
   모든 `/api/**`가 무인증 통과다. → **인증은 실기기 QA 대상 아님.** 토큰 검증기·JwtUtil 계약은
   서버 단위테스트로만 검증(§8-4). QA 팀에 반드시 공지.
2. **백엔드 메트릭스/분석 작업**(DailyReport, CohortFirstWeek, FocusStat, RoomVsSingleFocus,
   UserSessionDetail 등 미커밋)은 이번 릴리즈 범위에서 **제외**.
3. **룸 이력(BY-415)·퇴장 순공시간(BY-430)** 정확성은 클라 관찰 불가 → 백엔드와 협의해 **DB 조회 병행**(§8-3).

# 1. 공부 세션 측정 · 복원 (핵심)

> BY-447/448/449/452/455. 순공시간 정확성이 이 릴리즈의 심장이다.
> **불변식: 앱이 꺼져 있던/배경에 있던 공백 구간은 순공(studySec)에 절대 포함되면 안 된다(일시정지로 잡힘).**

## 1.1 정상 측정 · 스냅샷 보고

- [ ] **SESS-01** `[공통]` **P0** 세션 시작 후 30초에 첫 스냅샷, 이후 30초마다 보고
  전제: `?userId=N` 세션, 측정 중 / 기대: `PUT /api/study-sessions/active` 주기 전송, 화면 타이머 정상 증가
- [ ] **SESS-02** `[공통]` **P0** 카메라가 집중/비집중 감지 → 순공시간이 집중 구간만 누적, 비집중은 studySec에 남되 focusSec 제외
- [ ] **SESS-03** `[공통]` **P1** 스냅샷 보고 네트워크 실패/5xx: **사용자에게 오류 UI 없이** 다음 주기 재시도, 화면 정상
- [ ] **SESS-04** `[공통]` **P1** 스냅샷 400/404/409 응답: 그 세션 보고 **완전 중단**(무증상), 화면 세션은 그대로 진행 — 409는 서버가 이미 확정한 정상 상태
- [ ] **SESS-05** `[공통]` **P2** 보고 요청이 20초 매달리면 abort 후 다음 주기 재시도(하나가 이후 주기를 막지 않음)

## 1.2 강제종료 · 크래시 후 서버 자동 확정

- [ ] **SESS-06** `[공통]` **P0** 세션 진행 중(스냅샷 1회 이상 나감) 앱을 강제 종료(스와이프 kill)
  기대: 클라 제출 없이 **서버가 최대 6분 내 자동 확정**, 기록이 남는다(기록 목록/통계에서 확인)
- [ ] **SESS-07** `[공통]` **P1** 자동 확정 시 endedAt은 마지막 스냅샷의 클라 시계(reportedAt) 기준, 공백은 순공에 미포함
- [ ] **SESS-08** `[공통]` **P2** 순공 1분 미만 세션은 자동 확정돼도 기록 목록에 표시되지 않음

## 1.3 복원 — 웹뷰 리로드로 이어받기 (BY-452 GET /active)

> 시작 버튼을 **다시 누르지 않고** 세션 화면 웹뷰가 재생성된 경우.

- [ ] **REST-01** `[공통]` **P0** 진행 draft가 서버에 있는 상태로 룸 재진입
  기대: `GET /api/study-sessions/active?userId=N` 조회, 결착 전 **어두운 배경 게이트**(스피너 없음, 수백 ms)만 유지, 세션 훅 미마운트
- [ ] **REST-02** `[공통]` **P0** 200 복원 시 **누적 시간이 0에서 튀지 않고 처음부터** 화면에 표시, **일시정지(카메라 꺼짐) 상태로** 열림
- [ ] **REST-03** `[공통]` **P0** 시작 시각은 서버 startedAt 승계, 앱 꺼져 있던 공백은 일시정지 구간 → 순공에 미포함
- [ ] **REST-04** `[공통]` **P1** 재개 후 종료 시 최종 제출이 옛 기록을 대체해 **한 건**으로 남음(중복 세션 없음)
- [ ] **REST-05** `[공통]` **P1** 서버에 draft 없으면 404 → 즉시 새 세션(0분부터), 게이트가 잠깐 어두웠다 세션 화면으로
- [ ] **REST-06** `[공통]` **P1** 조회 400/409 → 새 세션 진행(Sentry 1회) / 네트워크·5xx → 1초 간격 2회 재시도 후 새 세션 / 5초 상한 abort
  **관찰: 어떤 실패에서도 결국 세션 화면에 도달해야 함(게이트 영구 차단=버그)**
- [ ] **REST-07** `[공통]` **P1** 복원 후 결과 화면 **일시정지 횟수가 사용자가 누른 횟수와 일치**(크래시 시점 일시정지 중이었으면 공백과 병합, 부풀지 않음)
- [ ] **REST-08** `[공통]` **P2** 복원 후 단말 시계를 뒤로 돌려도 누적값이 깎이지 않고 이벤트가 세션 구간 밖으로 안 나감

## 1.4 시작 버튼으로 새로 시작 → 옛 세션 자동 마감 (BY-452 POST /recovery)

- [ ] **REST-09** `[공통]` **P0** 시작 버튼(홈 집중 시작/온보딩 완료/초대코드 입장/방 만들기)을 누르면
  화면 전환 **전에** `POST /api/study-sessions/recovery?userId=N`로 옛 세션 마감(200=확정·draft삭제, 404=없음)
- [ ] **REST-10** `[공통]` **P0** 마감 후 룸 조회는 404 → **새 세션으로 시작**(옛 시간 안 찍힘). 강제종료 후 시작 버튼 재진입 시 이어받지 않는 것이 의도된 동작(옛 기록은 마감으로 보존)
- [ ] **REST-11** `[공통]` **P1** 마감 실패: 200/404 외 실패는 1회 재시도, 그래도 실패면 **막지 않고 진행**(4초 상한). 못 한 세션은 서버가 5분 뒤 자동 확정
- [ ] **REST-12** `[공통]` **P2** (소셜룸) 이미 들어온 방의 자리 TTL 갱신(`renewLiveRoomSeat`)은 마감을 호출하지 않음 → 방금 복원한 세션을 지우지 않는지 확인

## 1.5 복구 판별·확인 카드 (BY-455 POST /recovery, "이어하기 아님")

- [ ] **SESS-09** `[공통]` **P1** 비정상 종료 후 홈 재진입 시 미확인 자동확정본 요약 카드 노출(`POST /recovery` 200)
- [ ] **SESS-10** `[공통]` **P1** 카드 확인 후 재호출 시 404 — **한 번만 노출**(재노출 안 됨)
- [ ] **SESS-11** `[공통]` **P2** 마지막이 정상 제출본/이미 확인/기록 없음 → 404(카드 안 뜸)
- [ ] **SESS-12** `[공통]` **P2** 자정 걸친 자동확정 세션은 카드에 **한 건으로 집계**(시작=최소, 종료=최대, 시간=합)

## 2.2 초대코드 입력 · 입장 (성공/무효/만료/정원)

> **BY-436 핵심**: 404가 세 종류(`INVITE_CODE_NOT_FOUND`/`ROOM_CLOSED`/`USER_NOT_FOUND`) — 본문 `code`로 분기.

- [ ] **INV-07** `[공통]` **P0** 유효 코드 입장 → 룸 이동. `POST /api/rooms/join {userId, inviteCode}` 200
- [ ] **INV-08** `[공통]` **P1** 4칸 입력: 숫자만, 앞자리 0 보존("0712"), 붙여넣기/OTP 자동완성 4자리 한 번에 처리, **완성 시 키보드 자동 내림**, **자동 제출 없음**("참여하기"로만)
- [ ] **INV-09** `[공통]` **P1** 무효 코드(없는 코드/형식위반) → "초대코드를 다시 확인해 주세요"
- [ ] **INV-10** `[공통]` **P1** 만료·소멸 방(`ROOM_CLOSED`) → "방이 만료되었어요"
- [ ] **INV-11** `[공통]` **P1** 정원 초과(6명 찬 방, 409 `CONFLICT`) → "방이 가득 찼어요"(누가 나가면 재시도 가능)
- [ ] **INV-12** `[공통]` **P2** 사용자 확인 불가(`USER_NOT_FOUND`) → "사용자 정보를 확인할 수 없어요"
- [ ] **INV-13** `[공통]` **P2** 5xx·네트워크 → "잠시 후 다시 시도해 주세요", 다시 입력 시작하면 이전 에러 문구 사라짐
- [ ] **INV-14** `[AND]` **P1** 4칸 입력 포커스 시 **네이티브 커서(캐럿)가 엉뚱한 곳에 노출되지 않음**(`caret-transparent`, BY-444). iOS도 확인
- [ ] **INV-15** `[공통]` **P2** 코드 형식 위반(`abc`/`123`/`12345`) → 400 `BAD_REQUEST`, 서버가 `\d{4}` 검증
- [ ] **INV-16** `[공통]` **P2** 이미 A방 참여 중 B방 입장 → A방 자동 퇴장(SWITCHED_ROOM). 단 B가 가득이면 A 유지한 채 409

# 3. 소셜룸 — P2P 영상 · 타일 · 회전 · 복귀

> FE live-room. **이 영역은 iOS/Android 플랫폼 차이가 가장 많다.** 실기기 2대 이상 필수.

## 3.1 다인 영상 표시

- [ ] **VID-01** `[공통]` **P0** 2대 이상 같은 코드 입장 후 각자 카메라 켜기 → **서로의 타일에 영상 표시**
- [ ] **VID-02** `[공통]` **P0** 입장은 **무조건 카메라 꺼짐(일시정지)으로 시작**(입장 미리보기 모달 없음). 하단 카메라 버튼 → 켜기 확인 모달로만 켬
- [ ] **VID-03** `[공통]` **P1** 셀프뷰는 전면 카메라 시 거울(좌우반전), **상대에게 가는 송신은 원본**(반전·필터 미적용)
- [ ] **VID-04** `[공통]` **P1** 상대가 카메라 끄면 그 타일이 **아바타(닉네임 첫 글자 원형)**, 다시 켜면 영상 복귀
- [ ] **VID-05** `[공통]` **P1** 연결 실패 상대는 에러 UI 없이 조용히 아바타(순공시간·상태는 STOMP로 계속 갱신)
- [ ] **VID-06** `[공통]` **P2** 트랙 도착해도 패킷 흐르기 전(muted)엔 아바타 유지, unmute 시 영상(검은 화면 방지). 프레임 끊기면(onmute) 정지 프레임 대신 즉시 아바타

## 3.2 타일 그리드 재배치 (인원 증감)
