# 출시 전 백엔드 운영 QA — 데이터 정합성·로그 (BY-610)

실기기 앱으로 **dev 서버(EC2 docker compose: app + postgres)** 에 요청을 보내고, 그 결과가 DB와 로그에
의도대로 남는지 백엔드가 직접 확인한다. 화면 동작은 기존 릴리즈 QA 체크리스트(2026-08-28)가 다루고,
이 문서는 **"서버에 뭐가 어떻게 쌓였는가"** 만 본다.

- 진행: 백엔드 1인, 실기기 2대(다인 방·RTC 항목에 필요). 두 번째 기기는 에뮬레이터로 대체 가능하나 RTC는 실기기 권장
- 검증 쿼리: `docs/qa/sql/ops-qa.sql` (항목의 `→ B-2` 같은 표기가 그 파일의 섹션 번호)
- 표기: `[ ]` 미검증 / `[x]` 통과 / 실패 시 항목 아래 메모. **P0** = 출시 게이트, **P1** 중요, **P2** 여유 있으면
- 인증(JWT)은 파킹 상태라 userId는 `POST /api/users`(기기 UUID)로 발급받은 값이다

## 스코프 밖 (읽고 시작)

- **CloudWatch·Sentry·Slack 알람 파이프라인은 이번 QA에서 검증하지 않는다.** dev 서버에는 awslogs 드라이버도
  Sentry DSN도 없다. BY-609(로그 유저 컨텍스트)가 prod에 배포된 뒤 실트래픽 관찰로 갈음한다 (§D 마지막 표).
- 일일 Slack 리포트(10시, prod 프로파일 전용)도 같은 이유로 제외.
- 자정 분할(B-8)은 시계 조작이 필요해 P2. 서버 단위테스트가 이미 덮고 있다.

## 방식 — 세 가지 원칙

1. **QA 유저를 고정하고 모든 쿼리를 그 userId로 스코핑한다.** 기기 2대로 `POST /api/users`를 한 번씩 호출해
   응답의 userId 두 개를 psql 변수 `:uid`, `:uid2`에 넣는다. dev DB에 다른 데이터가 섞여 있어도 영향이 없다.
2. **시나리오마다 "조작 → 기대 행 → 쿼리"를 한 묶음으로 본다.** 조작 직전에 기준선(A-2)을 찍고, 조작 후
   증가분만 본다. 비동기 기록(룸 이력)은 응답 후 1~2초 뒤에 조회한다.
3. **마지막에 불변식 스윕(§D, 쿼리 D-1~D-11)을 돌린다.** 시나리오별 확인은 "내가 한 조작"만 잡는다.
   불변식 스윕은 조작과 무관하게 "이런 행은 존재하면 안 된다"를 테이블 전체에서 잡아 예상 못 한 버그를 건진다.
   전부 0행이어야 통과.

### 시간 압축

| 대기 항목 | 원래 대기 | 압축 방법 |
|---|---|---|
| 강제종료 후 자동확정 | 유예 5분 + 스캔 1분 = 최대 6분 | 앱을 죽인 뒤 쿼리 B-3으로 `last_seen_at`을 6분 전으로 돌리면 다음 틱(≤60초)에 확정 |
| 방 끊김 유예 | 30초 | 그대로 대기 |
| 빈 방 만료 | 10분 | 인메모리 TTL이라 압축 불가. 그동안 다른 항목 진행 |
| 스냅샷 버퍼 flush | 5초 | 조회 전 5초만 기다리면 됨 |

### 로그 보는 법 (dev)

dev 프로파일은 사람이 읽는 텍스트 로그라 MDC(userId·requestId)가 **패턴에 없어 보이지 않는다.** QA 동안만
compose의 app 서비스에 환경변수 하나를 얹어 prod와 같은 ECS JSON으로 바꾼다. 코드 변경 없이 prod 로그
포맷을 미리 리허설하는 효과도 있다.

```yaml
# docker-compose.yml (dev EC2) app 서비스
environment:
  LOGGING_STRUCTURED_FORMAT_CONSOLE: ecs
```

```bash
docker compose up -d app                                   # 재기동
docker compose logs -f app | jq -c 'select(.userId=="12")' # 유저 12의 모든 로그
docker compose logs app | jq -c 'select(.requestId=="<X-Request-Id 값>")'
docker compose logs app | jq -r 'select(.log.logger|endswith("RequestLoggingFilter")) | [.["@timestamp"], .userId, .message] | @tsv'
```

QA가 끝나면 환경변수를 빼고 다시 올린다.

### 출시 후 실트래픽으로 확인할 것 (이번 QA 대상 아님)

| 확인 | 어디서 | 기대 |
|---|---|---|
| ECS JSON에 `userId`·`requestId` 최상위 필드 | CloudWatch Logs Insights `filter userId = N` | 유저별 흐름 조회 가능 |
| 4xx/5xx가 Sentry에 릴리스(commit SHA) 태그로 도착 | Sentry 이슈 | 5xx 한 건 = 이슈 한 건 |
| ALB 5xx 알람 → Slack | CloudWatch 알람 · Slack 채널 | 5분 내 2건이면 알람 |
| 매일 10시 일일 리포트 | Slack | DB 집계와 수치 일치 |
| 액세스 로그 볼륨 | CloudWatch 로그 그룹 저장량 | 하루 증가량이 예상(요청 수 × ~300B) 안 |
