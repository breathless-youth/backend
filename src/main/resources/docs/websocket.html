1. 연결과 인증

항목값
엔드포인트wss://<API 호스트>/ws — 순수 WebSocket. SockJS는 쓰지 않는다 (@stomp/stompjs의 brokerURL)
인증CONNECT 프레임 헤더 Authorization: Bearer <access 토큰>. 핸드셰이크 URL 쿼리에는 토큰을 싣지 않는다(ALB 액세스 로그에 남는다)
인증 실패헤더가 없거나 토큰이 무효하면 서버가 ERROR 프레임(인증이 필요합니다 / 유효하지 않은 토큰입니다)을 보내고 소켓을 닫는다. 사유는 ERROR 프레임의 message 헤더에 담기고 본문은 없다
토큰 만료검증은 CONNECT 시점 한 번. 접속 중 access가 만료돼도 세션은 유지된다. 재접속 전에 갱신해서 붙이는 것은 클라이언트 몫
heartbeat서버 제안 10000,10000(ms). 클라이언트도 heartbeatIncoming: 10000, heartbeatOutgoing: 10000으로 맞춘다. 0이면 비활성
const client = new Client({
  brokerURL: "wss://<API 호스트>/ws",
  connectHeaders: { Authorization: `Bearer ${accessToken}` },
  heartbeatIncoming: 10000,
  heartbeatOutgoing: 10000,
});

2. 입장 흐름

입장은 REST와 STOMP 두 단계다. POST /api/rooms/join은 자리 예약(30초)이고, /topic/room/{roomId} 구독이 입장 확정이다. 30초 안에 구독하지 않으면 예약은 소멸한다.

다이어그램은 CDN(jsdelivr)에서 Mermaid를 받아 그린다 — 회색 상자만 보이면 네트워크 차단이다.

sequenceDiagram autonumber participant FE participant API as REST participant WS as STOMP participant Room as 방 토픽 FE->>API: POST /api/rooms/join {inviteCode} API-->>FE: 200 {roomId, graceRejoin, cameraOn, iceServers, iceTtlSeconds} (자리 예약 30초) FE->>WS: CONNECT (Authorization: Bearer) WS-->>FE: CONNECTED FE->>WS: SUBSCRIBE /user/queue/room FE->>WS: SUBSCRIBE /topic/room/{roomId} (= 입장 확정) WS-->>FE: /user/queue/room ← SNAPSHOT {members[]} WS-->>Room: /topic/room/{roomId} ← MEMBER_JOINED {member}
순서가 중요하다. /user/queue/room을 /topic/room/{roomId}보다 먼저 구독한다. SNAPSHOT과 ROOM_UNAVAILABLE은 큐로 오는데, 큐 구독 전에 발사되면 사라진다.
  • graceRejoin: true는 같은 방에 내 자리가 아직 살아 있어(끊김 유예 중 등) 재입장한 경우다. 이때 cameraOn은 이전 값이다. 새 입장, 예약만 있고 아직 확정 전인 자리의 재요청, 이미 확정된 멤버가 join을 다시 부른 경우(ICE 자격 갱신 등)는 모두 false·null이다 — false가 자리를 잃었다는 뜻은 아니다.
  • 이미 다른 방에 있으면 그 방에서 자동 퇴장된다(그 방 토픽에 MEMBER_LEFT). 동시 1룸.
  • join 실패는 REST 응답으로 온다: 400(코드 형식), 404(INVITE_CODE_NOT_FOUND / ROOM_CLOSED / USER_NOT_FOUND — 본문 code로 구분), 409(정원 6명 초과).
  • 방 생성은 POST /api/rooms → 201 {roomId, inviteCode, emptyTtlSeconds}. 생성자도 join으로만 입장한다.

3. 목적지

구독과 발행 모두 허용 목록만 통과한다. 목록 밖 프레임은 조용히 버려진다(ERROR 프레임 없음).

방향목적지조건
구독/user/queue/room누구나. SNAPSHOT·ROOM_UNAVAILABLE은 요청한 세션에만, SIGNAL은 그 유저의 모든 세션에 온다(§6)
구독/topic/room/{roomId}그 방에 자리(예약 또는 확정)가 있는 유저만. 아니면 프레임을 버리고 요청 세션에 ROOM_UNAVAILABLE을 보낸다. 정확히 일치해야 하며 와일드카드 구독은 거부
발행/app/room/{roomId}/state인증된 세션만. /topic·/queue로 직접 SEND하면 버려진다(브로커에 위조 이벤트를 싣는 우회 차단)
발행/app/room/{roomId}/signal
발행/app/room/{roomId}/snapshot

4. 클라이언트 → 서버

세 메시지 모두 발신자가 그 방의 확정 멤버이고, 지금 세션이 그 유저의 최신 세션일 때만 처리된다. 아니면 응답 없이 무시된다(옛 탭·옛 기기의 세션은 자동으로 무력화).

4.1 /app/room/{roomId}/state — 내 상태 보고

{ "cameraOn": true, "focusState": "FOCUS", "focusSec": 1520 }
필드타입의미
cameraOnboolean, 선택카메라 켜짐 → 방에 CAMERA_CHANGED
focusState"FOCUS" | "DISTRACTED", 선택Vision AI 판정 → 방에 FOCUS_CHANGED
focusSecint ≥ 0, 선택순공 타이머 누적 초(주기 보고) → 방에 STUDY_TIME
  • 필드는 모두 선택이다. 보낸 필드만 반영되고, 반영된 필드마다 이벤트가 하나씩 나간다(셋 다 보내면 이벤트 3개).
  • 무효한 값(모르는 focusState, 음수 focusSec)은 그 필드만 무시하고 나머지는 반영한다.
  • 옛 이름 studySeconds는 받지 않는다.

4.2 /app/room/{roomId}/signal — WebRTC 시그널 중계

{ "toUserId": 34, "kind": "OFFER", "payload": { "type": "offer", "sdp": "v=0..." } }
필드타입의미
toUserIdlong, 필수같은 방의 확정 멤버여야 한다
kind"OFFER" | "ANSWER" | "CANDIDATE", 필수그 외 값은 무시
payloadany, 필수서버는 해석·저장하지 않고 그대로 전달한다(SDP, ICE candidate 등)

대상 유저의 /user/queue/room으로 SIGNAL이 간다(§5). 자기 자신에게도 보낼 수 있으나 의미는 없다. 프레임 한 개는 16 KB를 넘을 수 없다(§10).

4.3 /app/room/{roomId}/snapshot — SNAPSHOT 재요청

본문 없음(있어도 무시). 요청한 세션에만 SNAPSHOT을 다시 보낸다. 방 상태는 바뀌지 않는다. 확정 멤버가 아니거나 옛 세션이면 아무 응답이 없다 — 재시도가 조용히 소진되게 설계돼 있다.

5. 서버 → 클라이언트

모든 메시지는 JSON이고 type으로 구분한다. "방 토픽"은 /topic/room/{roomId}, "내 큐"는 /user/queue/room.

type어디로언제필드
SNAPSHOT내 큐입장 확정 직후, 또는 재요청에 응답members[] — 나를 포함한 확정 멤버 전체. 예약만 하고 아직 토픽을 구독하지 않은 자리는 보이지 않는다
MEMBER_JOINED방 토픽누군가 입장 확정(재입장 포함)member
MEMBER_LEFT방 토픽명시적 퇴장, 유예 만료 자동 퇴장, 다른 방 입장으로 자동 퇴장, 예약(30초) 만료. 확정 전 자리가 만료되면 MEMBER_JOINED를 본 적 없는 userId의 MEMBER_LEFT가 올 수 있다 — 모르는 id는 무시한다userId
CAMERA_CHANGED방 토픽누군가의 state 보고에 cameraOn이 있을 때userId, cameraOn
FOCUS_CHANGED방 토픽… focusState가 있을 때userId, focusState
STUDY_TIME방 토픽… focusSec이 있을 때userId, focusSec
SIGNAL내 큐누군가 나에게 signal을 보냈을 때fromUserId, kind, payload
ROOM_UNAVAILABLE내 큐토픽 구독이 거부됐거나 확정에 실패했을 때(자리 회수·옛 세션)roomId

6. WebRTC 시그널링

서버는 시그널을 중계만 한다. 누가 OFFER를 내는지(예: userId가 작은 쪽), 재협상 정책은 FE끼리의 약속이다. ICE 서버 목록과 자격은 join 응답의 iceServers·iceTtlSeconds로 받고, TTL이 지나면 join을 다시 호출해 새 자격을 받는다.

sequenceDiagram autonumber participant A as FE(A) participant S as 서버 participant B as FE(B) Note over A,B: 둘 다 입장 확정(SNAPSHOT/MEMBER_JOINED로 서로를 안다) A->>S: /app/room/{roomId}/signal {toUserId:B, kind:"OFFER", payload:sdp} S-->>B: /user/queue/room ← SIGNAL {fromUserId:A, kind:"OFFER", payload:sdp} B->>S: /app/room/{roomId}/signal {toUserId:A, kind:"ANSWER", payload:sdp} S-->>A: /user/queue/room ← SIGNAL {fromUserId:B, kind:"ANSWER", payload:sdp} par ICE A->>S: signal {toUserId:B, kind:"CANDIDATE", payload:candidate} S-->>B: SIGNAL {fromUserId:A, kind:"CANDIDATE"} and B->>S: signal {toUserId:A, kind:"CANDIDATE", payload:candidate} S-->>A: SIGNAL {fromUserId:B, kind:"CANDIDATE"} end
  • 수신자가 확정 멤버가 아니거나(예약만 한 상태, 이미 퇴장) 발신 세션이 최신이 아니면 조용히 버려진다. 상대가 응답하지 않으면 SNAPSHOT을 재요청해 멤버 여부를 확인한다(§9).
  • SIGNAL은 대상 유저의 큐로 간다. 같은 유저가 두 세션을 열었다면 둘 다 받을 수 있으나, 최신 세션만 signal을 보낼 수 있다.

7. 끊김·재접속·유예

소켓이 끊기면(앱 백그라운드, 네트워크, 서버 배포) 자리는 30초 동안 유지된다. 이때 방에 이벤트는 나가지 않고, SNAPSHOT의 disconnected: true로만 드러난다. 재입장 join을 부른 뒤 토픽을 다시 구독하기 전까지는 그 멤버가 members[]에서 잠시 빠졌다가, 확정되면 MEMBER_JOINED로 돌아온다. 30초 안에 돌아오면 자리가 그대로이고, 넘기면 자동 퇴장(MEMBER_LEFT)이다.

sequenceDiagram autonumber participant FE participant S as 서버 participant Room as 방 토픽 FE--xS: 소켓 끊김 (앱 백그라운드·네트워크·배포) Note over S: 자리 유지 30초, members[].disconnected = true alt 30초 안에 재접속 FE->>S: POST /api/rooms/join {inviteCode} S-->>FE: 200 {graceRejoin: true, cameraOn: 이전 값, iceServers} FE->>S: CONNECT → SUBSCRIBE /user/queue/room → SUBSCRIBE /topic/room/{roomId} S-->>FE: SNAPSHOT S-->>Room: MEMBER_JOINED {member} (다른 멤버는 upsert) Note over FE: WebRTC 피어 연결을 다시 맺는다 (§6) else 30초 초과 S-->>Room: MEMBER_LEFT {userId} Note over FE: 이후 join은 새 입장(graceRejoin: false). 방이 이미 닫혔으면 404 ROOM_CLOSED end
  • 재접속 절차는 최초 입장과 같다: join → CONNECT → 큐 구독 → 토픽 구독. join은 유예 중이면 자리를 새로 잡지 않고 graceRejoin: true로 답한다.
  • 다른 기기·탭에서 같은 계정으로 들어오면 새 세션이 최신이 되고, 옛 세션의 발행은 모두 무시된다.
  • 서버 배포로 소켓이 닫혀도 같은 절차다. 방 상태는 DB에 있어 배포를 넘겨 유지된다.
  • 다른 멤버 입장에서는: 상대의 피어 연결이 끊긴 뒤 SNAPSHOT을 재요청하면 disconnected를 볼 수 있고, MEMBER_LEFT가 오면 피어를 정리한다.

8. 퇴장과 방 소멸

sequenceDiagram autonumber participant FE participant API as REST participant Room as 방 토픽 FE->>API: POST /api/rooms/{roomId}/leave API-->>FE: 204 API-->>Room: MEMBER_LEFT {userId} (남은 멤버가 있을 때만) Note over API: 마지막 1명이 나가면 방·초대코드 소멸. 그 코드로 join하면 10분간 404 ROOM_CLOSED, 이후 INVITE_CODE_NOT_FOUND FE->>FE: 소켓 DISCONNECT
  • 퇴장 API를 못 부르고 앱이 종료돼도 소켓 끊김 30초 후 자동 퇴장된다.
  • 생성 후 10분 안에 아무도 입장하지 않은 방도 소멸한다.
  • 퇴장 순서: leave API 먼저, 소켓은 그다음에 끊는다. 소켓을 먼저 끊으면 30초 동안 disconnected로 남는다.

9. FE가 처리해야 할 것

상황처리
토픽 구독 후 SNAPSHOT이 오지 않음구독 등록과 SNAPSHOT 발송의 레이스로 드물게 사라진다. 1~2초 뒤 /app/room/{roomId}/snapshot을 재요청하고, 몇 번 재시도해도 안 오면 join부터 다시 한다
ROOM_UNAVAILABLE 수신자리가 회수됐거나(예약 30초 초과, 유예 만료) 옛 세션이다. join을 다시 호출해 자리를 잡거나, 404면 방 종료를 안내한다. 이 메시지는 배달이 보장되지 않으므로 "SNAPSHOT 미도착"과 같은 처리로 수렴시킨다
피어 연결 실패·끊김10초 주기로 SNAPSHOT을 재요청해 멤버 목록을 재대조한다(배포 겹침 구간의 유령 멤버 보완). 목록에 없으면 피어를 정리하되, 재입장 직후엔 잠시 빠질 수 있으니 곧 MEMBER_JOINED가 오면 다시 맺는다. disconnected면 대기
MEMBER_JOINEDuserId 기준 upsert. 이미 있는 멤버면 재입장이므로 피어 연결을 다시 맺는다
access 토큰 만료세션은 유지된다. 재접속이 필요해질 때 갱신한 토큰으로 CONNECT한다
ICE 자격 만료iceTtlSeconds 경과 전에 join을 다시 호출해 새 iceServers를 받는다(자리는 유지된다. 접속 중인 멤버의 재호출이므로 응답은 graceRejoin: false·cameraOn: null이며, false가 자리를 잃었다는 뜻은 아니다)

10. 수치 한눈에

항목값비고
